# 当前 ScaleBFM 专家逻辑与 VLA 信息边界审计

日期：2026-09-09。范围：当前 `yplus_center_v1`、`expert_config()` / 原生29维动作专家及采集、导出接口。旧 Goal 保持停止；没有启动训练或重跑旧实验。下述“事实”是代码/测试证据；“风险”尚未经过 VLA 闭环消融验证。

## 结论

新专家运行现在强制检查头部相机在 **reset t=0、任务前 t=1.60s、实际第一帧学生录像**能看见瓶子。第一帧检查也覆盖延后开始的恢复数据。合格数据必须全部通过；不会用手腕相机可见替代头部可见。失败保留并计入尝试，不静默换 seed。

判定沿用已有感知阈值：头部相机瓶子分割像素≥32、robot-unoccluded fraction≥0.2。这保证最小图像证据，不保证瓶子完整入镜、RGB 检测器一定识别成功或全程无遮挡。fraction 的分母是“隐藏机器人后的同一视野”，**不能代表全部遮挡比例，也不能检测视野外裁切**。

**学生接口未发现物体/桌面真值直接输入；专家仍不是纯 RGB policy。** 其三维瓶子中心、桌面高度与边缘来自仿真代理；延迟与量化不能证明这些信息可以从 RGB 可靠推断。当前不应宣称已经得到“最适合 VLA”的策略。

## 完整运行链

| 步骤 | 当前行为 | 信息来源与限制 |
|---|---|---|
| 场景采样 | 只从 y+ 接近；瓶子沿桌中部±8cm，近处向内12–18cm、深处18–24cm；机器人距边1.1–1.3m、侧移±20cm、朝瓶方向±20° | `visual_sampling.py`；真值用于布置环境允许，但这是受限任务分布 |
| 稳定站立 | 0–1.68s保持初始站位/手臂；正常学生录制从1.60s开始 | 初始可见性失败时仅执行稳定站立至1.62s，保存拒绝记录；不进入任务 |
| 感知 | 每0.4s渲染头部与手腕分割图，过门限才产生几何；瓶子坐标按相机坐标量化5mm | `visual_sensor.py`；真值代理，非 RGB 定位算法 |
| 信息交付 | 80ms延迟；遮挡不刷新瓶子位置，最多保留1s衰减记忆 | `visual_observation.py`；精细运动还要求当前可见/置信度≥0.5 |
| 走近 | 根据瓶子、桌边法向计算站位；距离站位≤0.5m开始抬手 | `visual_planner.py`；不是先走完再抬手 |
| 预抓取 | 距站位≤10cm且手掌距预抓点≤3.5cm，转入伸手，锁住当时实际机器人位置与朝向 | 实际停点是到达阈值内的动态位置，不是每集严格到同一个坐标；进入后不再自动向桌移动 |
| 合拢 | 手掌沿接近方向误差≤2cm、横向误差≤1.8cm、速度≤0.1m/s才下达合拢 | 瓶子中心下方2cm作为抓点；合拢完成以命令值判断，不是物体接触真值 |
| 抬起/搬运 | 夹爪命令到阈值后抬手12cm；看到瓶子相对合拢前位置抬高≥8cm才进入回收；目标抬高12cm，后收7cm | 本次去掉了“桌高+固定瓶半高8.2cm”判定；使用已经观察到的合拢前高度 |
| 动作生成 | 50Hz生成连续参考、分阶段插值、受限跟踪积分；25Hz原生29维动作交给共用执行器 | `visual_motion.py` / `visual_action.py` / `visual_executor.py`；部署不会额外获得专家伺服 |
| 录制 | 动作前记录同一时刻两路RGB、本体91维及上一动作，再保存当前动作标签 | `visual_recording.py` / `visual_camera.py`；恢复片段第一帧单独检查，不额外向 planner 交付感知 |
| 停止/验收 | 真值用于掉落、碰倒、姿态、抬起成功与结束；成功稳定1秒结束 | 这是审计/选择通道，不是直接输入；仍会影响训练集分布和片段长度 |

桌高的影响：高度权重在约0.621m到0.761m间插值，站位前后距离及桌边安全间隔随高度改变，高桌间隔约15cm、低桌至少22cm。机器人骨盆目标高度仍是0.76m；低桌前倾主要由手部目标与底层全身控制产生。**不存在显式的“先判断够不够，不够再选择弯腰”的动作规划器**。

## 已复现并修复

1. **初始可见性没有验收门。** 旧审计只统计任务阶段到合拢的可见比例，t=0不可见但后来可见仍可 accepted。新增 `visual_visibility.py` 共用检查；runner阻止进入任务；审计、A基线样本选择及新数据导出也检查。A仍是冻结真值对照，不把它改称视觉专家。
2. **相机选择不符合可见性门限。** 两相机中一个通过即可读取几何，但旧代码取像素最多的相机，可能选择遮挡比例不合格的一路。现仅在两项阈值都通过的相机中选择。
3. **同一次阶段切换的朝向不一致。** reach→entry锁实际根部yaw后，手腕四元数及误差分解仍用切换前yaw。现立即重算同一帧的接近轴和手腕朝向。
4. **固定瓶高导致假抬起。** 旧代码以瓶心z减去桌高+0.082判断抬升，较高瓶尚未运动就能从lift转carry。现记录合拢时可见瓶心高度，用后续可见位移判断。仍存在历史记忆，不宣称消除了部分可观测性。
5. **恢复数据首帧不等于1.60s。** 对实际开始录制时刻取独立图像证据（包括blackout）；不把此额外采样送入专家tracker。导出时核对证据时间与student首帧时间，缺失则拒绝。历史文件不会自动补写为通过。

拒绝的初始化会保留稳定站立轨迹及一帧合法形状的学生记录（若启用录像），避免零帧录像/数组造成后续恢复失败；它们 `ok=false`，不能导出成训练样本。

## 仍存在的先验与潜在问题

| 优先级 | 事实 | 对 VLA 的风险/处理建议 |
|---|---|---|
| 高 | 通过瓶子可见性后直接读取 `sim.crate()` 三维中心；分割也按目标 geom ID 精确识别 | 学生没有同等精度/语义 oracle；小图像误差也可能导致专家过精细动作。后续应以真正 RGB 估计器或经校准的视觉不确定性实验验证；5mm量化不等于视觉现实性 |
| 高 | 只检查瓶子可见就读取 `smeta['surfaces']['A']` 的桌高、中心、半宽，未验证桌边是否在视野中 | 瓶子可见而桌边不可见时仍能用精确桌边决定停点，这是明确的信息可得性缺口。需要桌面/边缘观测门与置信度、或真正视觉几何估计；本次没有把读取真值包装成解决方案 |
| 中 | 第一次看到瓶子时按机器人世界朝向最接近x/y轴选桌边，并固定此route | 暗含桌子与世界轴对齐；旋转桌子或换方位不保证泛化。应以观察到的桌边法向决定接近方向 |
| 中 | 专家有阶段、锁定站点、抓前高度、积分误差、插值计时；学生只有当前/0.4s前图像、当前本体和上一动作 | 相似学生观测可能对应不同教师动作。不是“把phase喂给学生”就该解决；应检验观测相似度下的动作歧义，比较合理历史窗口/事件式控制。尚未测其对VLA的具体贡献 |
| 中 | `close→lift`依据夹爪命令阈值；没有实际夹爪状态/视觉持物确认；阶段基本单向，未提供失败后的重抓/重定位 | 命令已闭合不保证抓到；学生难从成功筛选数据学失败恢复。可先用本体夹爪位置/速度和视觉相对运动验证，不需要contact真值 |
| 中 | 高/低桌站距插值、固定左偏15cm、预抓后退10cm、抓点下偏2cm、始终右手、固定骨盆高度 | 多数是可学的任务动作规则，不能直接称为真值泄漏；但限制姿态、尺寸和可达性泛化。当前“低桌自然弯腰”没有独立可达性规划保证 |
| 中 | 恢复扰动由专家phase+固定延迟触发；部分数据从扰动后开始 | 起始分布与学生自身错误不完全一致，也可能缺少之前的动作历史；不是已证明有效的DAgger |
| 中 | 真值成功/碰倒判定终止并筛选数据，B/C姿态等审计有额外筛选 | 允许用于评估，但训练分布会偏向成功容易态，缺少失败恢复。必须用固定预算VLA闭环比较，不能只看教师成功率 |
| 低 | 遮挡fraction只消除机器人遮挡；32像素是最小门限，没有框边距/完整入镜门限 | 当前保证“可见证据”，不保证完整瓶身或可识别性。扩大随机化时应另做首帧RGB检测率/框面积/边界覆盖分析 |

学生接口检查：`state_features()`只返回关节、夹爪、重力、相对手腕位姿、自身速度和上一动作；相机接口只提供RGB与固定任务文字。`right_wrist_abs_quat` 名字有误导，实际是root-relative四元数，未读物体真值。部署 `predict(obs)`不接收审计sensor的结果。动作编码使用当时自身根部参考系，没有未来物体状态列。
