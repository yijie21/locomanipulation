# 走近、下蹲和抓取的切换

采集侧现在将“到位”“下蹲已执行”“可以开始伸手”分开检查。执行侧增加了默认关闭的下蹲前缀保留实验。2026-09-05 的完整诊断见 `outputs/diag/transition_validation_20260905/REPORT.md`；修复与新对照保存在 `outputs/diag/transition_fix_20260905/`。

## 采集侧

`stream_reach._creep_to_band()` 返回 `ApproachResult`，状态为 `ready`、`timeout` 或 `fallen`。调用方只在 `ready` 后创建手臂控制器。检查到位的 0.2 s 期间停止平移；失败时清除行走指令。旧的 `target_rel` 参数仍可传入，但不再决定停止时刻，`GYM_CREEP_OBS=0` 也不能恢复隐藏随机目标的停止规则。

下蹲前、下蹲后的**深度**统一在仅绕 yaw 旋转的骨盆坐标系检查；手臂 IK 继续使用完整姿态的骨盆坐标系。预停靠范围由后续允许范围减去现有 8 cm 后移先验得到，并与 0.18–0.27 m 的接近范围求交。8 cm 是预测值，不是保证；实际下蹲交付量、下蹲后深度和方位角仍须通过检查，随后基于测得的手腕姿态重新生成抓取计划。

调用方也不再用随机 `plan_r` 改变这些范围。当前公共下蹲后筛选带为 0.22–0.40 m；先导成功轨迹实际覆盖约 0.294–0.381 m。这个上界是本次瓶子场景的经验筛选值，其他桌高/物体尺寸需要继续校准，不能解释为通用可达性证书。

这不是完整的三维碰撞自由可达域。现有 servo/IK 和碰撞监测仍负责动作执行中的检查。实际下蹲造成的位移、距离、抓取是否开始，都写入 manifest 的 `transition` 字段；不能仅用“走到 0.45 m 内”判断抓取可行。

`GYM_ONE_SHOT=1` 时，不在失败片段后追加重新调整再抓取的恢复序列。失败尝试由现有 exporter 丢弃机制处理，成功轨迹保留原始连续时间，没有删除等待帧或提前动作标签。

## 动作执行侧

默认 async 执行行为保持不变。比较三个实验：

1. 默认：每 0.4 s 请求新预测，返回后按时间对齐接管。
2. `--rtc`：已有的 RTC 前缀约束，冻结长度覆盖推理延迟。
3. `--rtc --transition-commit --transition-decoder PATH`：实验性保留模型预测中的下蹲过渡。

第三组仅支持 64 维 SONIC token、async、`--ensemble 1`。它读取 WBC 的关节位置、速度、惯性信息和历史目标，无瓶子真值、真值距离或 privileged 触发。先观察到腿部运动，随后稳定直立时，将预测 token 在测得的同一份 WBC 历史下解码；如果未来连续三帧双膝都明显屈曲，保留到该过渡之后最多四帧。每次计算前，先用历史 token 重建实际目标，解码校准不通过便不触发。

保留截止时间锚定于原预测的观测时间，后续重规划只能缩短剩余冻结长度，不能重启倒计时。新的预测在 RTC 中以这个已承诺前缀为条件续写，客户端仍按绝对时间补偿推理延迟。观察到实际双膝屈曲后停止触发。一次保留不超过原来 40 帧的时间范围，异常结束沿用原有 VLA/WBC 停止机制。

这是可部署信息上的启发式执行实验，**不是已训练好的阶段分类器**。未来 token 的固定历史解码也不是物理 rollout。必须同时检查 trace 中的 `transition_commit_events`、`transition_commit_errors`、`rtc_requests`、实际发送 token 和身体运动，不能将开关已打开当成机制已生效。

## 小批数据与检查

本次验证数据：`datasets/g1_transition_pilot_20260905`，5 条成功轨迹，共 3,052 帧，25 Hz。最终统一筛选条件后的训练数据是 `datasets/g1_transition20_train`，15 条成功轨迹，共 8,733 帧。两者保留完整导航、下蹲、伸手、抓取和抬起。

`meta/transition_events.jsonl` 由 `tools/label_transition_pilot.py` 将原始 `priv_seq` 与 pose sidecar 精确匹配后生成。它提供阶段事件时刻及对应数据帧索引，不会作为模型输入，也不会自动改变现有训练采样权重。这 5 条先导轨迹留作独立验证；继续训练使用另外采集的 15 条轨迹。增加历史观测、阶段辅助头或切换片段重采样需要单独消融，本轮先隔离新示范数据的作用。

续训结果保存于 `outputs/train/transition_pilot20_20260905/checkpoint-300`。从原 cover400 checkpoint-10000 继续训练 300 步，学习率上限 2e-5，有效 batch 64；处理器归一化与原 checkpoint 完全一致。本次仅验证可见目标的近距离初始化，没有覆盖 3 m 外目标不可见的导航。

本次闭环小样本：旧模型默认 1/3、普通 RTC 2/3、长切换前缀 0/3；续训模型默认 2/3、普通 RTC 0/3。续训模型默认组三次均在约 7–9 s 内下蹲，但一次始终没有夹爪闭合。因此保留采集侧检查，执行开关继续默认关闭，不能据此宣称最终抓取问题已解决。详细结果及限制见 `outputs/diag/transition_fix_20260905/REPORT.md`。

## 2026-09-06 原地接管与运输姿态检查

实际第一帧 XY 校正已移至观测流准备完成之后；这是诊断开关，不改变正常初始化，也不是完整控制器状态复现。确认瓶子仍直立、维持原骨盆高度后，提前原地专家接管三次成功两次，一次在手掌运输阶段碰倒瓶子。因此部分下蹲姿态可抓，但不能将全部失败归因于动作窗口。
