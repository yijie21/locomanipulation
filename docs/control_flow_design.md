# 动作控制流的渐进重构

## 目标

保留 SONIC、IK 和现有动作表示，逐步把桌面任务从实验脚本中分离。结构验收和物理成功率验收分别进行：代码更容易复用不代表专家或 VLA 已经更可靠。

## 第一批已迁移的调用

```text
grasp_gym.run_round
  ├─ 创建本次 ExecutionRecord
  ├─ 初始化、导航（原控制逻辑）
  ├─ TabletopGrasp.initial / replan（桌面目标几何）
  ├─ stream_reach.execute_grasp
  │    ├─ approach：实际到位判据
  │    ├─ arm_control：获得手臂控制
  │    ├─ posture / posture_correction：下蹲及旧恢复逻辑
  │    ├─ reach_validation：实际交付状态与重规划检查
  │    └─ grasp.up / down / in / close / lift：原连续伺服
  ├─ verify_visibility / carry_and_verify
  └─ 返回 RoundResult → manifest
```

`ExecutionRecord` 每次尝试独立创建；`GraspResult`、`RoundResult` 保存返回时的深复制快照。失败记录保留最先报告错误的控制阶段与原始原因，外层的 `[grasp]` 包装和最终 `failed` 不覆盖它。它不是离线物理失败分类器，不能由它断言瓶子第一次倾倒或接触发生的精确时刻。已有完整捕获和 `failure_taxonomy` 仍负责物理事件审计。

manifest 保留 `transition`、`park`、`park_first` 等旧字段，增加 `execution`。该字段有版本号、阶段事件、单调时钟相对时间及 Unix 墙钟时间。记录的是控制代码进入阶段的时间；servo 子阶段在该阶段第一次循环开始时记录。它不等于图像曝光时间、动作实际生效时间或身体到位时间。模型观测/预测/发送记录尚未迁移进这个时间结构，不改原 trace 时钟。

正常采集入口不再读取 `ROUND_STATS` / `LAST_TRANSITION` / `LAST_EGO_VIS` 作为返回结果。旧 `grasp_streamed` 入口暂保留 tuple 与 LAST_* 快照，供旧 `collect_episode` 和诊断脚本兼容；该兼容入口不保证并发隔离。新任务必须使用 `execute_grasp` 的返回值。`RoundResult` 可按原来的三个值解包。

录制失败依然使用 exporter 的丢弃路径；现在录制已开始而控制代码抛异常时也执行丢弃，然后继续抛出异常。成功录制的保存时机不变。进程崩溃或丢弃命令本身失败的恢复不在本批保证范围内；异常中断时也不能假设 manifest 已落盘。

## 场景与任务接口

`TabletopTarget` 明确声明目标 key、手侧、抓取高度、支撑面高度和物体包围盒；`TabletopGrasp` 集中计算初始候选与基于当前观测的重新规划。调用方不再复制方位锚点、进刀方向和避让方向的公式。

这仍是现有直立桌面物体的策略。抓取高度仍由调用方按现有瓶口偏移规则产生；固定停靠深度、下蹲先验和上限尚未转成场景可校准配置。没有为抽屉、把手、倒瓶等不同交互方式假造通用接口。左右手几何对照通过不代表整个任务已支持左手：导航等现有代码仍有右手假设。

## 后续迁移及验收

1. **当前贯通片段**：每次尝试的状态/结果/阶段记录，桌面抓取几何抽取。验收：旧规划公式一致；失败后不可继续伸手；回合结果不串写；录制失败清理；正常专家路径实际执行。
2. **停靠、下蹲与安全伸手**：把经验阈值集中为显式配置，并将完整手掌运输路径与实际下蹲状态纳入可行性检查。扫横向站位、朝向、桌高、初始手姿；记录所有尝试，分开统计采样/视野拒绝和实际抓取失败。先解决碰撞，再扩大随机停靠范围。
3. **执行通道与动作时序**：用显式 Planner / token 适配替换全局 Commander 改写。定义唯一的控制权交接过程和观测时间锚定；验证迟到 chunk、RTC 前缀和停止行为。既有异步执行机制、动作表示和默认窗口先保持，逐项对照。
4. **数据与模型验证**：在完好目标片段中区分未预测、未发送、发送未交付；据此补充完整连续示范或调整模型/执行。训练前审计时间对齐，训练后独立初始化评估，不能以专家成功率替代 VLA 成功率。
5. **扩展验收**：不同桌高/物体，再迁移“抓起—运输—放置”。3 m 目标不可见时的搜索/接近需要单独定义可获得的观测和训练任务，不由抓取模块隐式解决。

本批还保留 `VLA_POLICY` 全局选择、旧函数参数和部分环境变量；没有完成通用任务编排器，也没有建立完整仿真/控制器状态快照。逐项替换后才能称为完整控制流重构。

## 第二批进展（2026-09-06）

已将接近/下蹲的主要经验参数集中到 ReachConfig，并给正常专家采集接入主动臂运输阶段的局部碰撞筛查。完整无碰撞路径规划、身体运动预测和经动态验证的随机停靠可行域尚未完成。配置、适用范围和验证见 [reach_feasibility.md](reach_feasibility.md)。

## 第三批进展（2026-09-06）

已加入仅用于诊断的关节路径规划与受保护执行，明确区分“找到路径”“实际交付预抓取姿态”“抓起保持”。动态结果显示，静态 IK 成功不能替代末端交付验收；终点也不能要求冗余机器人必须收敛到唯一关节解。生产控制流尚未迁移到该路径执行器，原因是实际跟踪与站位失败仍未解决。

下一项物理验收应先固定下蹲姿态，标定 PlannerArm 的参考→实际关节/末端响应及身体漂移，再决定采用任务空间闭环运输还是调整底层参考接口；不要通过放宽到位判据让失败进入训练集。执行通道适配与动作时间锚定仍按上面的第 3 项单独迁移。实验范围和证据见 [reach_feasibility.md](reach_feasibility.md)。

## 第四批进展（2026-09-06）

完成空地固定参考响应测量：当前 Planner→SONIC 存在稳态上肢跟踪偏差，且身体几何随上身参考变化。修复了新诊断脚本的重复阻塞观测导致的降频，并在原速保持中复核了偏差。下一项物理验收收敛为受约束的末端闭环与可跟踪姿态选择；没有将静态路径或常数关节补偿接入默认采集器。详见 [arm_response.md](arm_response.md)。

## 第五批进展（2026-09-06）

末端反馈拆为纯参考提议与受保护执行：`PoseFeedback` 不发布、不认定物理成功；执行器负责状态新鲜度、碰撞、漂移、时间预算和实际到位。诊断路径可在最终参考处接入该执行器，漂移起点与时间预算不在交接时重置。空地低速两次通过，桌前需单独验收，尚未启用为默认采集。

同一控制 tick 的观测应复用。新反馈已向 PlannerArm 的另一只手避让传递当前测量，避免内部第二次阻塞读取导致降频；旧调用尚未迁移。这给后续执行通道重构提供了具体接口边界，不能继续以函数名里的“50 Hz”代替实际时间记录。

## 第六批进展（2026-09-06）

完成 9 个请求站位的脚本短接近→下蹲→诊断运输/反馈→抓取：4/9 抓起并保持，5/9 交付预抓取姿态；失败包括两条反馈无进展、一条 in 阶段推瓶、一条身体漂移越界、一条接近朝向未达标。不是 VLA 评估，也不能按请求网格建立连续可抓区域。

新诊断复用 VLA 接管 helper 时暴露了重复朝向重设，已用显式 planner_active 入口修复并添加两种入口的回归测试。交接朝向改善不等于身体几何不变：停靠后到下蹲后仍有最大约 28 cm 水平漂移，此区间包含手臂接管保持；后续 helper 交接也只有 1/8 满足其记录的 3 cm XY/高度几何保持条件。应先拆分这些阶段的测量与验收，再选择可跟踪预抓取姿态并处理接触抓取失败。默认采集不启用新反馈，详细结果见 [stance_validation.md](stance_validation.md)。

## 第七批进展（2026-09-06）

完成接管/下蹲/保持分段与三个条件的诊断对照。`walk_to` 只承诺距离到达和发送 IDLE；将其返回值当作物理停稳不成立。诊断加入显式实测停稳门槛后，两条接管位移约 0.5 cm，而蹲姿转换仍有约 10–11 cm 水平变化。控制流应以实际阶段交付状态做下一步规划，不复用站立时的目标相对坐标。

新增可选上身命令参考交接入口，保留原调用默认行为。参考连续、速度稳定、身体几何保持是三个不同契约；其中一个满足不能替代另外两个。完整动作流程及默认采集尚未迁移这些诊断条件。本批 47 项测试通过，但全程 3 cm 漂移检查仍为失败；详细边界见 [stance_validation.md](stance_validation.md) 及分段报告。

## 第八批进展（2026-09-06）

诊断中贯通实测站稳→下蹲→实测蹲稳→重新规划→运输与抓取；三个请求站位各两次，6/6 完成稳定检查，3/6 抓起并保持。其余分别为腕部前向位置、姿态反馈饱和、动态净空拒绝，不将它们混为阶段切换失败。

已建立借用已活动控制器的入口，调用方保留清理责任；发现并修复运输函数内部再次重设参考的隐藏交接。参考连续性必须贯穿整个调用链，而不只在入口调用处成立。本批只显式启用于连续诊断，不改旧采集默认。独立场景覆盖消除了本诊断对共享场景的写入。

51 项测试通过，详细证据见 [stance_validation.md](stance_validation.md)。运输循环的实际周期仍约为名义 DT 的两倍；下一步优先复用同 tick 观测并核对速度参考，再复测可跟踪预抓取及动态净空。后续采集、训练及独立 VLA 评估仍未完成。

## 本轮收尾：停止追加结构重构（2026-09-06）

运输循环已复用当前观测；固定六次完整回归，1,509 个调用间隔中位 21.03 ms、p95 24.78 ms，原系统性双阻塞已消除。51 项测试通过。完整抓取仍为 3/6，另有初始化站稳失败、中间姿态跟踪超时、腕部前向位置拒绝各一条；不建议启用为默认大批采集。详见 [时序修复报告](../outputs/diag/transport_timing_20260906/REPORT.md)。

本轮到此收尾，不再继续追加开关、阈值微调或泛化框架。后续使用 [collection_acceptance.md](collection_acceptance.md) 的三项验收：专家来源与适用域、实际训练数据时间对齐、VLA 独立评估。旧训练数据审计可直接进行，不要求先把专家在所有站位调到完美；专家失败也不能代替对原 VLA 桌前停住原因的验证。
