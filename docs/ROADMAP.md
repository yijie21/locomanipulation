# 路线图:从这里到大规模数据集

> 这是**内部排期**,不是使用文档。想知道代码怎么跑、怎么用,看
> [README.md](../README.md)。

按顺序做。每一步都可能打破规划器的假设,所以**每加一个随机化维度都要先跑 12 局
确认成功率没崩**,再采数据 —— 否则采到的是一堆废片。

### 第 0 节:已经验证过的,不要重做

- **动作质量**:不踱步、不撞桌、站定不跳变、抓取不悬停。12/12(seed 21)、6/6(seed 33)。
- **没有 sim 侧关节 pin**。抓取全程由 policy 自己完成(`GYM_ARM_PIN` 默认 0)。
- **latent 就是 action**(`diag_token_replay.py`):录下成功 episode 的 64 维 token,
  在 `NO_ENCODER=1` 的 stack 上用 protocol v4 喂回去,关节轨迹复现到 **0.2–0.9°**。
  开环回放不会抓到罐子(浮动基座把误差积分成 0.77 m 位移),这是开环的固有性质,
  不是失败 —— VLA 部署是闭环的。
- **Action 空间 = 66 维**(token 64 + 双夹爪 1+1),由 wire protocol 定死:v4 只运
  `token_state` + 可选夹爪,planner 指令没有通道。
- **数据集能被真 LeRobot loader 加载**,不只是手工检查 parquet。
- **token 是 1/16 量化的**(整条 episode 31 个取值,约 5 bit/维)→ VLA 输出头应该
  **分类**而不是回归。

### 第 1 步:摸清场景生成的参数化能力 —— **已完成(2026-08-22)**

结论:**桌高和物体尺寸都是廉价的,不需要 EmbodiedGen。**

- **重建整个场景 = 1.0–1.2 秒。**`outputs/scene/{mjcf,layout}` 还在,
  `build_sim_scene.py <scene_root> <out_dir>` 只是把它们重新组装,不跑任何生成模型。
- **桌高** = `scene_lib.SURFACE_TARGET_TOP["dining_table"]`,单位米。实现是把桌子网格
  **整体等比缩放**到这个高度(0.62 → ×0.823)。
- **物体尺寸** = `scene_lib.PRIMITIVE_OBJECTS["can"]` 里的 `radius` / `height` 两个数 ——
  罐子是 MuJoCo 原始圆柱,不是生成的网格。生成资产另有 `OBJECT_SCALE`(目前是空 dict)。
- **`reach_map.npz` / `wrist_map.npz` / `hand_points*.npy` 不需要重建** —— 它们是骨盆系
  和手的属性,和桌子无关。`outputs/scene/grasps` 已经没有代码在读。

**耦合(必须知道):**桌子是等比缩放的,所以桌**变高就变大**:0.62 → 0.72 时半宽
0.503 → 0.584 m。**但这被采样器完全吸收了**,而且是实测的不是推的 —— `grasp_gym` 的罐位
按 `scene_meta` 的实际 `half_extent` 采(桌沿内 4–8 cm),站位也按实际桌沿采。把采样器
在两个变体上各跑 4000 次:

| | 0.62 桌 / φ4.8×12 | 0.72 桌 / φ6.0×16 |
|---|---|---|
| 采样接受率 | 93.0 % | 92.5 % |
| 罐到桌沿 | 5.9 cm | 5.9 cm |
| 站位到桌沿 | 23.7 cm | 24.6 cm |
| 伸手深度 rel | 32.2 ± 0.6 cm | 32.7 ± 1.2 cm |
| 规划下蹲 | 10.0 cm | 10.0 cm |

桌面大了 8 cm/边、罐高了 14 cm、粗了 25%,几何难度**基本不动**。所以桌高与物体尺寸是
一条便宜的随机化轴,不需要重新调任何接近/站位常量。

**可行区间(实测 `plan_core_stand`,PELVIS_MIN 保持 0.598):**
真正起作用的量是**罐顶高度**,因为 `grip_z = obj_top - GRIP_BELOW_RIM`:

| 量 | 可行区间 |
|---|---|
| 罐顶高度 | **0.63 – 1.24 m**,连续 |
| 桌高(配 0.12 m 罐) | **0.51 – 1.12 m** |
| 罐直径 | ≤ **8.48 cm**(`HAND_APERTURE 9.48 − PINCH_MARGIN 1.0`) |

**这只是运动学可行性** —— 表示 `plan_core_stand` 能给出站位,不表示抓得到。ego 可见性
和真实成功率在 0.62 以外的任何高度都还没验过。

**还要写的代码(很小):**

- `build_sim_scene.py` 没有桌高/尺寸的 CLI 或 env 入口,现在只能改常量。加两三个参数。
- `diag_ego_geom.py` 的场景路径是写死的,没法指向变体场景。加个 `--scene` 参数。
- **按批随机化,不要按局。**sim 启动时才读 XML,所以换桌高要重启 stack(~40 s)。
  每 20 局换一次 = 摊到每局 2 秒,可以忽略;每局换一次会让 67 s 的 episode 变成 107 s。

### 第 2 步:上两个不需要重新生成场景的随机化

- **目标物体身份 + 指令**:桌上已有 plate / fork / napkin / orange,但目标永远是罐子,
  模型可以完全不读指令。把目标随机化并在指令里指名 —— **这是"抓取策略"和"VLA"的
  分界线**。注意 fork / napkin 是扁平的,dex1 平行夹爪多半抓不了,别放进目标池。
- **机器人初始位置与朝向**:现在严格在接近线后方 1.8 m、朝向 ±25°。加出生距离
  (1.0–3.0 m)、**横向偏移**、更大的初始朝向误差(到 ±90°)。转身必须发生在远处 ——
  近距离的 `face_target` 会让机器人原地转 110–160°,这是记录在案的坑。

### 第 3 步:验证(12 局)

成功率没崩再往下。崩了就先修,别继续叠维度。

### 第 4 步:外观随机化

物体/桌面材质与颜色、光照方向与强度、地面纹理、背景。**一样都没变过** —— 现在训出来的
模型很可能是在认"那个特定灰色的圆柱"。只改 material,不碰控制逻辑,零风险。

### 第 5 步:放开蹲深上限,然后上桌高与物体尺寸

前置(第 1 步之后**降级为增强,不再是阻塞**):

- ~~`PELVIS_MIN = 0.598` 是硬阻塞~~ —— 实测不是。保持 0.598 时可行桌高已经是
  **0.51 – 1.12 m**,真实餐桌 0.72–0.75 稳稳在区间内。放开 `PELVIS_MIN`
  (`IDEL_SQUAT` 实测能到 0.51,即 27 cm,见 `diag_squatmode.py --sweep`)只会
  在给定高度上多给瞄准格与余量,以及打开 0.51 m 以下的矮桌 —— 那已经是茶几不是餐桌了。
  真要改,记得重建 reach map。
- 每个桌高都要用 `diag_ego_geom.py` 复查罐子在决策点(约 1 m 外)是否可见:直立时
  可见区间是 0.15–1.77 m,而这个上限随物体高度变,桌子越矮远端越近。

然后才是:

- **桌高**(现在固定 0.62 m,真实桌子 0.72–0.75)
- **物体尺寸与高度**(现在固定 4.8×12 cm;夹爪开口 9.49 cm,所以 3–8 cm 直径都在能力内)。
  物体高度直接决定蹲多深 —— **现在蹲深永远是 13 cm,这个轴等于没训**。

### 第 6 步:大规模采集

一条约 67 s、4.7 MB。规模不是瓶颈(1000 条约 5 GB),但加上 5 个随机化维度后
200 条会被摊得很薄,先定目标数量。

### 以后再说

- **episode 内扰动**:接近/伸手途中推罐子(`pin_object` 现成),或给骨盆一个冲量
  (需要在 `privileged_pub` 加 `xfrc_applied`)。按之前的结论,**等第一批模型告诉我们
  缺什么再上** —— 如果失败是"轻微偏了然后越偏越远"就补扰动,如果是"完全没对准"
  就补多样性。
- **质量 / 摩擦 / 重心**:RGB 看不见却改变结果,进训练集会造成别名化。**只做评测集**。
- **完整任务**(抓起 → 搬运 → 放下):在 `collect_episode.py` 的 `FULL_TASK=1` 里,
  那条路径还没迁移到新控制逻辑。只有抓取的数据集上限比较低。
