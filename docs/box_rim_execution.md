# 箱体边沿抓取执行

本页描述[静态抓点规划](box_rim_planning.md)之后的仿真执行步骤：从机器人实际
停稳的状态规划，低速接近边沿，闭合双夹爪并试提。它是独立的物理验证入口，
不作为正式数据采集的成功认证。

## 输入与适用范围

沿用已知尺寸、壁厚和位姿的刚性开口矩形箱体模型。箱体坐标原点在外底面中心，
位姿四元数顺序为 wxyz。运行时使用仿真发布的机器人关节、骨盆和目标箱体位姿；
这是仿真真值闭环，尚未接入仅靠 RGB 的在线箱体估计。

抓点随实际停车状态重新选择。箱体位姿决定边沿在世界中的位置，机器人姿态
决定哪些抓点可达。初始化场景的位置不替代执行开始时的实测状态。

## 执行与判定

固定站位先规划；有限搜索未找到有效候选时，可通过 SONIC 做小步调整，停稳后
重新规划。调整必须产生实际移动，不能在操作过程中重置机器人、修改根节点位置
或强制绑定箱体。

原有分段执行模式选定抓点后，先以收拢的夹爪抬手，在箱口上方的安全空间张开，再进入预抓取、
边沿对齐、双夹爪闭合和小幅试提。静态抓取姿态只是可达性的依据；从实际姿态到
抓取姿态的路径还必须单独检查。检查使用实际夹爪关节，并覆盖张开过程，避免
“终点可达，但手指在途中穿过箱壁”的情况。

接近轨迹以足端和质心约束下的全身中间姿态连接；根节点平移只作为规划中的
预期状态，不直接写入仿真。机器人必须通过腿部动作和接触动力学达到这些姿态。
这是默认的 `execution.approach_mode: supported_pose`。显式选择 `planner_arms`
时，接近 IK 保持实测骨盆和腿部参考，使用旧专家的 PlannerArm 通道执行上身
动作，接近、张开、对齐、闭合和试提仍检查实测状态。它也受请求中的关节、
足端、质心和碰撞限制约束；模式名本身不放宽这些判据。

显式选择 `legacy_low_reach` 时，先用 PlannerArm 抬手避让，再从新的实测状态
调用旧低位抓取的 `plan_low_reach` 全身求解器。切换到 StreamedArm 后，从其
当前参考姿态开始，执行至少 4 秒的平滑关节与骨盆姿态插值，并发送关节参考速度。
后续手部调整保持计划的下肢和骨盆参考。求解器使用与执行检查一致的关节余量；
参考插值中的足部几何不能代替实测支撑检查。该模式目前仍有下述接近阶段的
参考坐标衔接问题，不能视为已完成的抓取策略。

阶段推进依赖
实测误差与连续观测；静态 IK 结果、关节指令或一次瞬间接触均不能证明抓取成功。
试提需要持续的双侧接触、实际箱体抬升，以及受限的相对滑移和倾斜。

每次尝试保留请求、规划结果、执行轨迹和明确的退出原因。未找到候选、无法停稳、
跟踪超时、接触不足及试提失败都属于需要保留的结果，不能从统计中删除。

## 连续双臂 expert 迁移

`execution.approach_mode: coordinated` 复用原 `VisualApproach` 和
`CoordinatedReach`：停稳后按实测箱体相对距离调整站位，再连续协调双手、
躯干和腿部参考。新箱子的局部抓点、抓取区域坐标轴和对象键显式传入，
不复用旧篮子的固定高度或名称；本分支输入来源标为 `simulation_truth`，
尚未接入原 expert 的相机可见性准入。

夹爪保持 OPEN，只有实测双手进入抓取区域后才递增闭合进度。
启用重置时，先完成准备姿态，再进行第二次初始化并接管；解除固定后
才开始录像。操作过程中不重置机器人或绑定物体。

参考关节、根朝向与参考位置取自同一个连续解；实测和参考足端锚定误差
仍逐 tick 计算并写入轨迹，但只作诊断，不再作为退出门限。只有结构验证为
world body 最低活动水平 plane 的足/踝接触按地面支撑记录，且不受 penetration
增长门限约束；足部接触桌、箱、墙或其他障碍仍会拒绝。初始
`CoordinatedReach` 的 `WholeBodyPose.reachable` 准入、连续 WholeBodyIK 的足端
和 COM 残差，以及其余碰撞与安全门限保持不变。走近距离受总行程预算约束，
抬升仍需双侧接触、保持时间和滑移检查。
站距等参数以 `coordinated_` 前缀配置；当前不支持含 forbidden intervals
的动态抓区，会明确拒绝。实际抓取能力仍须逐场景验证。

## 运行入口
[受管试跑入口](../scripts/probe_box_grasp.py)接受扩展的第一步 JSON 请求：保留
`scene_xml`、`target`、`box`、`planner` 和 `robot_state`，增加 `target_key`、
`execution` 和 `runtime`。`target_key` 对应场景元数据中的对象键；`target.body`
是 MuJoCo 刚体名。执行时始终用最新观测替换请求中的机器人姿态和箱体位姿。

`runtime` 指定 `scene_dir`、`gpu`、`instance` 和 `backend`；此入口需要
`backend.no_encoder: false`。场景目录必须同时包含 `scene_locomani.xml` 和
`scene_meta.json`。`robot_dxy` 是初始化相对场景起点的平移，`robot_yaw` 是
初始化绝对朝向（弧度），仅在 `reset_before_episode` 启用时生效。
`video_label` 启用该次诊断录像，输出目录中的源录像需要压缩后才能交付查看。
场景的 `scene_meta.json` 可用 `video_camera` 指定 XML 中的固定相机；本物流房间
使用配对渲染图的 `reverse_room`。未指定时沿用骨盆跟踪机位；无效相机名会报错。

执行字段由 [BoxRimExecutionConfig](reference/config_fields.md#boxrimexecutionconfig)
定义。先校验请求，再启动一次受管试跑：
```bash
source scripts/paths.sh
"$VENV_SIM_PY" scripts/probe_box_grasp.py REQUEST.json --output OUTPUT/result.json --dry-run
"$VENV_SIM_PY" scripts/probe_box_grasp.py REQUEST.json --output OUTPUT/result.json
```

`--dry-run` 不启动进程，也不创建输出。真实试跑关闭正式采集 exporter，退出时
只停止自己启动的 Stack。结果区分物理检查通过与明确失败；失败结果也应保留。
实现与试跑证据见 [2026-09-20 执行记录](handoff/box-rim-execution-20260920.md)。

## 验证边界

最新 `coordinated_square_ready_once` 已通过静态与原控制器准入，但在首个
连续伸手指令发送前被参考右脚/地面穿透增量检查拒绝（1.829 mm > 1.500 mm）。
实测碰撞列表未拒绝，夹爪保持张开；没有下探、夹紧或抬升成功证据。
完整记录见上述执行 handoff，本轮未追加尝试。

2026-09-20 的最新 `legacy_low_reach_attempt_v6` 已完成抬手避让、4.04 秒的
全身弯腰和张开夹爪，实测躯干前倾最大 22.64°、骨盆前倾最大 20.09°。
随后向箱沿上方接近的参考检查在起点被拒绝：它混用了实测关节与计划骨盆姿态，
得到约 20.40/19.48 mm 的参考足端偏差，超过静态 5 mm 门限。这不能证明实际
滑脚，也不是实测 20 mm 支撑门限被触发。尚未接触、闭合或试提；该参考坐标
衔接问题仍需修复。请求使用预先存在自接触的诊断跟踪余量 0.5 mm，绝对上限
仍为 0.5 mm，禁止新接触对且准备结束必须消除接触；默认值不变。

此前的 `planner_arms_ready_first_v3` 工程试跑已执行双臂准备、抬臂、张开夹爪和向箱沿上方接近，
使用 `reverse_room` 固定机位录像。在上方接近的第六个中间目标处，实测位置误差
约 49.9 mm，超过 35 mm 门限而停止；尚未闭合或试提，不构成物理抓取成功。

这次使用单独的 `planner_arms` 诊断请求：箱沿采样 9 点、质心位移上限 75 mm、
已有足底支撑压缩上限 10 mm、实测足端跟踪余量 20 mm；静态足端求解仍要求
5 mm。这些值记录在运行请求中，不代表正式采集配置或已验证的跨场景鲁棒性。
静态关节解现在预留与执行检查一致的关节余量。准备先于站位规划和行走；
每个接近中间目标按最新实测骨盆重新投影，命令到位后短暂停留再检查实际误差。

起点已有的浅自接触只在短准备阶段处理：参考路径要求原接触单调消退，实测
跟踪允许原接触对在有限深度包络内波动（默认初始深度 +0.25 mm，绝对上限
0.5 mm），禁止新碰撞，结束时必须实测无接触。该例外不延伸到正常接近和闭合。

已知几何模型不涵盖软纸箱变形、封闭箱、翻盖或任意网格的箱口识别。
物理试提只能证明该场景和该次尝试通过所记录的检查；跨尺寸、位姿、停车误差的
可靠性仍需覆盖这些变化的试验。背景视觉模型若没有活动碰撞几何，不构成碰撞保护。
