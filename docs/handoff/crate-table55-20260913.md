# Carry 55 cm 桌高验证 — 2026-09-13

这是对“先验证 55 cm”的机械行为试验：保留完整走近、双臂抓取和提起，
检验降低桌面能否改善弯腰与折腕。它使用 carry 的 privileged 诊断专家，
不替代 RGB 专家的信息可观测性验收，也不是正式 VLA 训练数据。

## 协议与场景

运行源码为 `6fa7d36`，任务/控制源码与 `99e28fe` 相同；本次仅增加独立的
场景准备脚本。SONIC v1.1、encoder 开启，GPU 0 / instance 1。
两组各 10 次、seed 11，先 55 cm 后 62 cm；所有失败都计入分母。
手掌目标俯仰仍为 60°，篮子名义内移仍为 4 cm，起始桌沿距离准入仍为
1.2–1.5 m；运动速度、加速度、接触和提起门槛均未调整。

原始场景是 `outputs/crate_motion_flow_20260913/scene_depth04/`。
通用生成器的 `--table-top` 会等比例缩放桌子，改变 XY 和桌沿，因此这次用
[`crate_table_height_20260913.py`](../../scripts/experiments/crate_table_height_20260913.py)
保持桌面 XY，仅缩短静态桌子网格的 Z、降低承托碰撞面及篮子初始 Z。
脚本只支持本次检查过的 62 cm 场景，拒绝覆盖已有输出。

MuJoCo 编译检查确认：桌面世界高度 0.62 → 0.55 m、篮子中心初始 Z
0.707 → 0.637 m；有效桌面碰撞盒半宽仍为 0.488008 / 0.488489 m，
厚度、质量、摩擦、接触参数、机器人关节与执行器参数一致。
改变了静态桌子网格的惯量，机器人及篮子的惯量未改。
桌沿距离沿用任务的元数据边界定义；该边界比承托碰撞盒每边宽约 1.5 cm。

产物根目录：`outputs/crate_table55_20260913/`。`protocol.json` 记录协议，
`scene_table55/height_verification.json` 记录编译几何及 XML SHA-256。
每组保留配置快照、实际模型/二进制哈希回执、启动命令、全部 manifest、
关节指令与观测、完整状态轨迹、伺服末态和原片。

## 结果与解释

55 cm 可以完成任务，腕部弯折较小；这组结果没有证明它能增加弯腰、让手臂
接近伸直或提高可靠性。继续作为独立调试场景保留，尚未替换默认场景。

| 指标 | 55 cm | 62 cm 新对照 |
|---|---:|---:|
| 全流程成功 / 全部尝试 | 6/10 | 5/10 |
| 进入伸手 / 完成合拢 | 7 / 7 | 5 / 5 |
| 实际初始桌沿距离 | 1.219–1.457 m | 1.218–1.460 m |
| 合拢前腰关节角，中位数 | 19.9° | 20.6° |
| 合拢前左右腕俯仰，中位数 | 21.0° / 22.6° | 40.8° / 41.4° |
| 合拢前左右肘角，中位数 | 57.5° / 34.4° | 63.7° / 45.0° |
| 合拢前躯干离竖直倾角，中位数 | 14.6° | 15.5° |
| 停稳与交接耗时，中位数 | 1.100 s | 1.042 s |
| 伸手早期骨盆角速度 P95，各集中位数 | 0.274 rad/s | 0.254 rad/s |

姿态行包含全部完成合拢的回合（7 / 5），不只挑成功回合。
55 cm 的腰角范围为 3.3–21.5°，成功子集的腰角中位数为 14.7°；
并非每次都明显弯腰。其左肘角范围 38.6–80.4°、右肘 19.9–75.5°，
“只调桌高即可使双臂近乎直线”的预期未通过此次验证。

55 cm 的四次失败：横向站位偏差两次（−10.3、−4.7 cm）、停得过近一次、
提起倾斜 15.5° 超过原有 15° 门槛一次。62 cm 的五次失败均为横向站位偏差。
55 cm 有 6/7 个伺服末态记录到腕部连杆碰篮子，62 cm 为 3/5；这是末态接触
快照，不是整段碰撞频率，也不能据此认定它造成了倾斜失败。
现有任务判据的成功不等于已经验证“只有指垫接触”的干净抓取。

相同采样标签中，只有 `01/05/07` 在两组都进入合拢。对应腕角（左/右）：
`01` 为 19.4°/19.5° 对 38.7°/30.4°，`05` 为 19.5°/24.5° 对 43.4°/51.1°，
`07` 为 32.6°/36.9° 对 28.3°/41.4°（均按 55 对 62 cm）。
这支持减小折腕的调试方向，但不是所有关节、所有回合都改善。

两组仍满足原来的指令限速 0.7 rad/s；有效间隔的指令加速度 P95 约为
2 rad/s²。骨盆角速度沿用上一轮最多 3 s 的窗口，55 cm 覆盖 2.21–2.97 s，
62 cm 为 1.98–2.98 s；窗口可能含接触，不能据此认证自由空间抖动或声称更平滑。
下一步应在 55 cm 下独立设计抓取朝向、肘部姿态及篮沿避碰，并继续检查站位。
本次没有继续调到 45° 或改变控制增益。

抓取姿态按每集 `grasp` 最后 0.3 s 的实际关节角中位数计算，按观测 seq 去重，
再汇总各集；同时分别报告进入伸手、合拢和成功的样本数。
躯干倾角从同 seq 的完整仿真 qpos 做 FK，取 torso Z 轴与世界竖直方向夹角。
它与腰关节角不同，不能只看下发腰指令就声称视觉上完成弯腰。

此前单姿态 CPU 筛选在固定骨盆与初始关节下得到 55 cm / 60° 时腰约 18°、
腕约 37°/51°；原始探针在 `outputs/crate_table_height_review_20260913/`。
它证明了该姿态附近存在几何解，不预测完整步行、反馈 IK 与接触中的最终姿态。
当前试验使用实际轨迹检验趋势，不把 CPU 的角度当作动态验收标准。

相同随机种子只保证采样命令相同。实际站位、姿态和进入抓取的回合会不同，
而且本次为顺序运行的小样本；成功率或角度差异不能直接解释成单一因果关系。
没有进行学生 VLA 训练，也没有重新验证 Isaac 离线渲染。

```bash
  --gpu 0 --instance 1 --scene outputs/crate_table55_repeat/scene_table55 \
  --out outputs/crate_table55_repeat/table55

  -m locomani.pipeline.run_crate_pilot --expert carry --rounds 10 --seed 11 \
  --gpu 0 --instance 1 --scene outputs/crate_motion_flow_20260913/scene_depth04 \
  --out outputs/crate_table55_repeat/table62
```

原始场景是保留的实验产物，不随 Git 下载；新安装须先生成并核对同等场景。
使用 worktree 时显式设置 `LOCOMANI_ROOT` 指向该检出，并遵循共享资源规则。
本次命令的绝对路径版本在两组 `commands.jsonl` 和 launcher 日志中。

测量入口（将路径换成本次或重跑的产物根目录）：

```bash
third_party/GR00T-WholeBodyControl/.venv_sim/bin/python \
  scripts/experiments/crate_table_joint_report_20260913.py outputs/crate_table55_20260913
third_party/GR00T-WholeBodyControl/.venv_sim/bin/python \
  scripts/experiments/crate_motion_report_20260913.py outputs/crate_table55_20260913 \
  --variants table55 table62
```

`joint_report.json` 含每集统计、轨迹哈希、接触末态、各子集及配对标签；
`motion_report.json` 含交接、指令和骨盆运动指标。全部姿态窗口的 seq 都匹配到
完整仿真轨迹。`identities.json` 核对两组任务配置、源码摘要、实际 SONIC
encoder/decoder、观测配置与 deploy 二进制相同；启动回执均为 encoder 开启。
`make check` 和提交检查通过；场景脚本已通过真实模型编译断言，报告脚本已消费
全部 20 次记录并核对十组采样命令。结束后 GPU 0 为 2 MiB、instance 1 锁和端口
空闲，GPU 1 的其他工作未停止。
