### What changed in behaviour

- `sealed.py`: a benchmark summary no longer carries `bucket1` and `prediction` (scene only). `gate.py` has its own `skills_hash` and imports `scene_round` only for a scene family. `try.py` no longer imports the scene runtime (`parse_set` moved to `batch.py`; `--steps` loads the scene `digest` lazily).
- `sandbox.py` draws pools through `backend.py draw <family> <pool> <out>` (a benchmark sandbox holds no `scene/`); a scene family's `keep` lists hold `scripts/rsi/scene`.
- Removed: `RSI_NO_SEALED`, the `repeat` cap, `iteration_line` (no caller), dead family keys (`plan: null`, `probe_bed`), the standalone `simple` / `lml` backends, the esc bed and `official_runner`, the families `simple_fake`, `lml_q`, `lml_fridge`, `lml_drawer` (`simple_q` is a bench family).
- Kept on purpose: `RSI_STUB_REAL_GATE` (the runbook names it), `RSI_REACH_*` / `RSI_ROUTE_*` / `RSI_GRIP_GUARD` (read by `batch.motor_config`, used by `experiments/grip_guard_20261110/replay.py` and tests; `batch.py` keeps its scene motor functions because tests and that script call `B.motor_signature`).
- A benchmark family with no `class_suggest` in its layout now gets `{}` (it used to fall back to the scene's class table).
