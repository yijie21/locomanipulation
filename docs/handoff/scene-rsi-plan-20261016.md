## 2. 结构

**外环**（一轮）：

1. **发现**：Claude 读场景文件、能力表、技能目录，提任务（谓词合取 + 3–5 句说法）。
2. **分桶**：程序检查每个任务的抓 / 搬 / 放步骤：① 现有技能可做；② 缺口——范围缺口（现有技能用在没测过的高度、尺寸、距离）或技能缺口（没有技能能做）；③ 超出（硬件或场景不支持，附原因）。结果回给 Claude 修改提议。
3. **选缺口**：按“解锁的任务数 ÷ 估计成本”排序，取前 K 个（D9）。
4. **内环**：每个缺口跑一次 RSI（下）。
5. **写回**：被接受的技能进技能目录，它在封存集上的实测结果进能力表；回到 1。

**内环**（一个缺口 = 一组任务，D7）：warehouse 闭环原样，改三处——Engineer 可以写或改技能（D6）；成败由谓词判；三池从这组任务的场景随机摆放里抽。

**第 0 轮之前**：闭环用 motor 层跑探针，测出 mars + ScaleBFM 的能力表（D10）。

## 6. 风险

- **抓取一直是最难的一环**：闭环写的新抓取（地上、台面高处、窄物体）可能长期过不了门；预算耗尽也照报。
- **多步任务的成功率是乘积**：三步各 70% 只剩约 34%；跨房间任务还要过门（没测过）。
- **ScaleBFM 站立脚外滑**：长任务里会累积，可能要在 motor 层里处理。
- **补了家具碰撞体以后**，现有的导航和站位规划可能大量受阻。
- **泄漏**：封存集、验收池逐局结果、其他副本里的答案，沿用 warehouse 的目录隔离和 transcript 审计。
- **场景许可**：ADT 衍生物不能分发（Demo 1 决策 17）；MolmoSpaces 的许可还没查。

### 7.3 ADT 家具碰撞（27.2.5，2026-10-16）

- `scripts/adt_to_scene.py mujoco --furniture-collision robot`（默认）：每件家具加一个凸包碰撞体，碰撞位 `contype 4 / conaffinity 0`，机器人的 42 个碰撞体 `conaffinity` 1 → 5。于是凸包只和机器人碰，自由物体照旧放在台面板上（凸包会填满柜格，物体不能和它碰）。

- 重建后：128 个凸包；机器人在起点不碰任何凸包；推车前复位抓罐子同前（抬起 7.6 cm）；从起点直线走过去这次没摔，但伸到罐子差 3.5 cm、没抓住（单次）。

### 7.4 任务运行器（27.2.3，2026-10-16）

- 代码 `src/locomani/tasks/scene/`：`world.py`（场景 + motor + 占用图 + 谓词状态）、`start.py`（起点）、`navigate.py`（绕障）、`episode.py`（一局 → `RoundResult`）、`skills/`（技能库，闭环以后写这里；现有种子 `pick` v0）。单测 `tests/test_scene_task_runner.py`，实测 `scripts/experiments/scene_rsi_20261016/episode_check.py`。
- 起点：任务物体在自己的台面上随机换位置和朝向（带朝向的矩形不相交，避开台面上所有没动的物体——不是自由体的也会碰：咖啡罐摆到推车托盘上一秒内被弹下）；机器人在任务房间的出生区随机，离物体 1–3 m，要求占用图上能走到物体旁。成败用 `compile_goal` 的谓词（= 19.10.2，运行器这条路已接上）。
