# selfmodel_relabel_20261125：把轨迹中间点当作新起点、标签仍用最终落点，能不能代替真实的"停稳后慢速进入"数据

- **日期**：2026-11-25。在任何训练之前写好，单独提交。
- **机器**：4090，在 1–3 号卡里挑空的用。
  - 必须在 [selfmodel_train3_20261125](selfmodel_train3_20261125.md) 开训（约 13:00Z）之前跑完。来不及就让出卡。
  - 4090 的 CPU 正在被采集占满，所以训练只开 4 个 CPU 线程。
- **代码**：`selfwm`。
  - 训练：`reachwm_20261030/train.py E3_ensemble`，配方原样：3 万步，batch 1024，5 个成员，seed 0。
  - 环境变量：`REACHWM_GOAL_REF=1`，和 `models_goalref_wrist_odo` 一样。
  - 中间点样本：用一个新脚本生成，存成和原数据同样布局的 npz。`data.py` 和 `train.py` 一行不改。
- **数据**：ScaleBFM 在我们自己仿真里的旧数据，`loco_outputs/simple_selfmodel_20261119/` 下的 `data_graspr_odo` 和 `data_graspr_wrist_odo`。
  - 每次重置走完以后伸三下：开点、预抓取（抓取点后方 10 cm）、慢速进入（0.08 m/s，参考从中点开始）。

- **用户的提议（2026-11-25）**：一次伸手录下了整条手的轨迹，把轨迹上的不同位置都当作起点，输出都用最后的落点，这样也许不用专门补采短伸手。用户决定先测这个办法，同时照常补采（[selfmodel_data3b_20261125](selfmodel_data3b_20261125.md)）。

## 假设

我的看法是这个办法替代不了真实数据。理由有三条：
1. **中间点上手在动，不是停稳的。** 模型读出发前三帧，看得出速度。从静止起步的那一下（加速、重力下垂、小幅度时停不准）不在这些样本里。
2. **控制器在中间点正跟着一条早已发出的参考**，参考比身体超前，ScaleBFM 超前 0.16 s。真在那里重新发命令，参考会从当前点重新规划，速度和时长都不同。
3. **速度和距离不一样。** 中间点剩下的路程是 0.15 m/s 长伸手的尾巴；抓取时是从停稳状态以 0.08 m/s 伸 5–12 cm。

不过这些样本毕竟是真实发生过的，能教会模型"手在这附近时控制器的偏差往哪边"。所以我预计它比完全没有短伸手要好，但比不上真实的慢速进入。

## 三个模型（只有训练集不同，验证和评估完全相同）

- **C（对照）**：只用开点和预抓取两种伸手，不用进入段，也不加中间点。
- **A（用户的办法）**：C 的数据，再加上从这些伸手里切出的中间点样本。
  - 每一段从命令后 0.3 s 开始，每隔 0.2 s 取一个新起点，取到离结束 0.3 s 为止。
  - 新起点的前三帧就是那一时刻的真实状态。
  - 命令仍是原来的目标和手腕朝向，换到新起点那一刻的骨盆朝向坐标系里表示。
  - 参考特征：终点姿态不变；"相对起点的变化"按新起点重算；时长改成剩下的参考时长，最少取 0。
  - 标签不变，仍是那一段最后停稳的落点。
- **B（真实数据）**：C 的数据，再加上真实的进入段。

## 度量

- **主要**：在验证集和 test_iid 的真实进入段上，模型预测落点的误差中位数（cm）。
  - 只算出发前停稳的那些段：用力的那只手在命令前 0.5 s 内的速度低于 2 cm/s。
  - 给出 A/B、C/B、A/C 三个比值，区间按重置重抽样算 95 %。
  - 同时报"手停在命令处"的误差，也就是不用模型、直接执行的误差。
- **次要**：在开点和预抓取的验证段上，A 和 C 的误差。用来看中间点样本会不会伤到长伸手。

## 预测

- B 在进入段上：0.3–0.9 cm。旧模型的总体验证误差是 0.568 cm。
- C/B：1.5–4。没有进入段，相当于在数据范围外。
- A/B：1.3–2.5。
- A/C：0.6–0.95。中间点样本有一点帮助，但补不齐。
- 长伸手上 A 和 C 相差不超过 ±10 %。

## 判据

| 结果 | 结论和下一步 |
|---|---|
| A/B ≤ 1.15，并且区间上限 ≤ 1.3 | 中间点办法可行。以后换控制器时，不再专门补采短伸手，改用中间点样本；data3b 本轮照常采完，用来作对照 |
| A/B ≥ 1.3 | 中间点办法替代不了真实数据，补采是必要的。A/C < 0.9 的话，中间点样本可以作为附加数据，合并训练时另外测 |
| 两者之间 | 换 seed 1 再跑一次 A 和 B，再下结论 |
| 长伸手上 A 比 C 差 10 % 以上 | 中间点样本会伤到长伸手。不管上面哪种结论，都不能直接混进训练 |

注意这个测试用的是我们自己仿真里的 ScaleBFM，不是 LML 宿主里的三个控制器。它只回答原理上行不行。

## 预测修订

### 修订 1：实现时的几处读法（在冻结 10:34:59Z 之前定下，看到结果之后才补记）

这些都是实现时自己定的读法，正式运行之前已经定下来，预测和判据都没有因此改动。

1. **从哪一行开始切**："离结束 0.3 s"按"离这一段的最后一行"来算。每段结尾都带着参考结束以后 1.0 s 的静止，所以 A 的中间点里有 57.6 % 落在参考结束之后：这些起点的手已经基本停住，离落点只剩中位数 0.38 cm。
2. **取哪些段来切**：只从训练划分里的开点段和预抓取段切。落在 band 或 edge 里的段不切，摔倒的段不切。换坐标系以后目标落进 band_x 的中间点也丢掉，共占 7.8 %。
3. **C 怎么去掉进入段**：只去掉训练划分里的进入段，所以三个模型的 val、test_iid、band、edge 逐段完全相同（`split_check.log` 显示 PASS）。
4. **怎么认出进入段**：用段在这次重置里的位置认，第 3 段就是进入段。
5. **出发前 0.5 s 的停稳窗口**：进入段在命令之前只录了 0.3 s，不够的 0.2 s 用同一次重置里预抓取段的最后 0.2 s 补上。
6. **另外加了一个模型 Am（未登记）**：C 的数据，再加上 A 里参考还没结束的那部分中间点，共 186012 个，起点手速中位数 17 cm/s。它是在冻结之前加的，但当时已经看过一次冒烟的输出（300 次重置、200 步，数字没有参考价值）。下结论时不用它。

## 意外

1. **A/C = 0.56**，比预测的 0.6–0.95 还低，也就是中间点样本帮的忙比我预计的大。不过它离 B 仍差一倍：0.80 cm 对 0.37 cm。
2. **长伸手上 A 比 C 好 9–15 %**。预测是两者相差不超过 ±10 %，方向我没有想到。可能是因为中间点样本把手臂在这片区域里的偏差教得更细了。
3. **中间点有 58 % 落在参考结束之后**，几乎是"已经到了"的样本。只保留参考还在跑的那部分（Am），进入段的误差也只降了 8 %（Am/A 0.92），结论不变。
4. **B 和 C 后期过拟合**，checkpoint 分别选在第 8000 和第 6000 步；A 的数据多了 13 倍，一直训到第 30000 步。

## 结论与下一步

- **结论**：在这一份数据上，"轨迹中间点当起点"替代不了真实的"停稳后慢速进入"数据。
  - 进入段误差 A/B = 2.18，95 % 区间 [2.08, 2.27]，val 和 test_iid 分开算分别是 2.22 和 2.14；
  - 按判据，"A/B ≥ 1.3"成立，补采是必要的。
- **中间点样本作为附加数据有用**：
  - 进入段 A/C = 0.56；
  - 长伸手上不但没伤到，反而更好，A/C 在 0.85–0.91 之间。
  - 按判据，合并训练时另外测一组"data3 + data3b + 中间点样本"。
- **证据强度**：
  - 1 个控制器（ScaleBFM），在我们自己的仿真里，不是 LML 宿主；
  - 1 个 seed，每个模型训一次，5 个成员；
  - 评估用 2615 个停稳出发的进入段，来自 2615 次重置；
  - 区间按重置重抽样得到。
- **其他可能的解释**：
  1. A 的训练集比 C 大 18 倍，但训练步数和 batch 都一样，每个样本平均只被看到约 1/18 次。A 可能没有训够。不过 A 的 val 在第 24000–30000 步之间已经基本不动（0.446 → 0.443）。
  2. 中间点的切法不是唯一的。例如完全不用参考结束后的那些点，或者按"剩余距离"重新加权，结果可能不同。Am 是其中一种，只改善了 8 %。
  3. 进入段的参考从中点开始、速度 0.08 m/s。这种参考形状在中间点样本里根本不存在。差距有多少来自"出发时没停稳"，有多少来自"参考形状不同"，这个实验分不开。
- **四类陷阱**：
  - **benchmark 选择**：评估集是登记时定的，全部进入段都算，只按登记里的停稳规则过滤，不是挑出来的容易样本。
  - **数据泄漏**：三个模型的 val 和 test_iid 逐段相同；中间点只从训练重置里切，`split_check` 显示 PASS。
  - **指标误用**：主度量用的是登记的中位数，p90 一起报了，val 和 test_iid 分开也都报了，没有换指标。
  - **事后挑选**：每个模型只训一次。checkpoint 由 train.py 按同一个 val 自动挑选，不是人挑的。Am 单独列出，没有参与下结论。
- **对照判据**：
  - 落在"A/B ≥ 1.3"这一格：补采必要，data3b 照常采；
  - A/C < 0.9：中间点样本作为附加数据，在合并训练里另外测；
  - "长伸手上 A 比 C 差 10 % 以上"没有触发。

> **指标误用：没有。** 主指标、比值、按重置重抽样的区间都和登记一致；p90 同向（A 2.16、B 1.27 cm）；分 val、test_iid、两个数据集看结论都不变。区间只反映样本抽样，不含训练 seed 的随机性，这次只跑了 seed 0。

> **A 的训练集大 18 倍、步数相同：** 每个成员看 3 千万次样本，A 每个样本约 66 遍，B 约 860 遍，C 约 1200 遍。A 的训练损失还在 3.5e-3（B 7.5e-5、C 9e-6，已背下训练集），val 从第 20000 步 0.452 降到第 30000 步 0.443，最后 4000 步基本走平，所以 A 可能略欠训练，会让 A/B 偏大；但要降到 1.3 以下，A 在进入段上得再降 40 %，和走平的曲线对不上。A 里的原长伸手只看了约 66 遍（C 1200 遍），A 在长伸手上反而比 C 好 9–15 %。C 在第 6000 步最好，之后 val 从 0.580 升到 0.615，这套配方对 C 步数太多；按 val 挑 checkpoint 抵消了一部分，但 A/C 里可能有一部分只是"数据多了起正则作用"，不完全是中间点内容本身的功劳。两边偏差方向相反，都没大到能翻转结论，但都没直接测。
>
> **机理旁证：** 全部中间点里"参考还在跑、手却停着（< 2 cm/s）"的只占 0.12–0.13 %。参考还在跑、剩余距离 5–12 cm 的起点，手速中位约 16.5 cm/s，剩余参考只有 0.56 s；真实进入段从静止出发，距离中位 11.6 cm，速度 0.085 m/s，参考 1.37 s。中间点样本几乎完全覆盖不到进入段的出发状态，和 A/B 落在 2 左右吻合。
>
> **可能推翻结论的实验：**
> - 针对"代替不了"：A、B 各训一个 12 万步的版本（余弦学习率也拉到 12 万步），原配方下补 seed 1、2；每 2000 步单独记 val 进入段中位数，test_iid 只在最后看一次。约 2 小时三张卡。长训练或多数 seed 下 test_iid 的 A/B ≤ 1.15 且区间上限 ≤ 1.3 就推翻；A/B 明显下降但仍 > 1.3，说明原比值高估但结论成立。
> - 针对"作附加数据有帮助"：B 的数据加中间点（D）和 B 在 test_iid 进入段上比，3 个 seed；再给 C 一套适合小数据的配方（6000 步余弦、加大 weight decay 或对 x0 加小噪声）作正则对照 C′。约 6 个模型，1–2 小时。D/B ≥ 1.0，或 C′ 在进入段上 ≤ 0.89 cm（A/C′ ≥ 0.9）就推翻。
>
> **判定：**
> - "这个办法代替不了真实的进入段数据（A/B ≥ 1.3）"：**支持**。pooled 2.180 [2.082, 2.274]，没参与挑选的 test_iid 2.135 [2.012, 2.263]，两个数据集分开都在 1.9 以上，Am 也还是 2.0。实现上没发现会冤枉 A 的错误。限定：只有一个 seed；A 可能略欠训练；只针对这个实现（特征里不含控制器当前的参考、E3 配方）、我们仿真里的 ScaleBFM 和 iid 区域。
> - "中间点样本作为附加数据有帮助（A/C < 0.9）"：**在登记的设定下支持；合并训练的情形证据不足**。A/C pooled 0.560 [0.535, 0.580]，test_iid 0.545，长伸手没变差（0.85–0.91）。但这只说明"完全没有真实进入段时"有帮助；和真实进入段合并时是否还有帮助没测，登记时也写了要另测。C 的配方明显过拟合、没有正则对照，说不清收益有多少来自中间点内容本身。A/C 0.56 低于预测，长伸手 A 好于 C 的幅度超过 ±10 %，都偏向有利一边，不触发"伤到长伸手"的判据。
