## 假设

用同一套采法采来的数据，三个控制器都能学出自身模型。条件是覆盖要全：原地和走完停稳都有，左右手都有，高度从 0.05 m 到 1.5 m，手腕朝向包括滚转和 ±90° 的偏转。在每一种拆分下，误差都应该接近总体，不能有某一块明显学不好。

## 度量

所有误差都是中位数，在验证集上算；另外报 test_iid 的数。只算没摔倒、没跑离、停稳了的段。

- **终点位置误差（cm）**：分两组报，模型预测的落点，和"手停在命令处"这个不用模型的假设。后者就是直接执行的误差。比值等于模型误差除以直接执行误差。
- **终点姿态误差（度）**：模型预测的姿态和实际姿态之间的测地角。同样报不用模型时的值。
- **拆分**：
  - 原地 / 先走路；
  - 右手 / 左手；
  - 高度段：z < 0.3、0.3–0.6、0.6–0.9、0.9–1.2、≥ 1.2 m；
  - 朝向段：|偏转| ≤ 60° 对 > 60°，|滚转| ≤ 40° 对 > 40°，俯仰 < 0° 对 ≥ 0°；
  - 站 / 蹲。
- **学习曲线**：三个 frac 的验证误差。
- **区间**：每一格都报段数，并按重置重抽样给出 95 % 区间。

## 判据

| 结果 | 下一步 |
|---|---|
| 某个控制器模型对直接执行的比值 > 0.5 | 先查标签：停稳窗口和延迟有没有对齐，跑离截断对不对。查清以前不加数据 |
| 先走路 > 1.5 倍原地 | 加采先走路的局 |
| 先走路 ≤ 1.2 倍原地 | 以后可以少采走路 |
| 从 frac 0.3 到 1.0 误差还降 10 % 以上 | 这个控制器加采，直到降幅小于 5 % |
| 某个高度段或朝向段 > 2 倍总体 | 在那一段加密采样 |
| 左右手相差 > 30 % | 查左手的镜像和采样有没有问题 |
| 姿态误差模型不比不用模型低 | 姿态这一项不进 claim，先查姿态标签 |

## 意外

1. **ScaleBFM 不如预测**：
   - 误差：val 3.08 cm、test 3.00 cm，预测 1.6–2.6 cm；
   - 和直接执行的比值 0.32，预测 0.15–0.28。

   旧的 hostdata 模型 val 是 1.88 cm，但那份数据只覆盖右手、俯仰 0–90°，没有滚转，也没有走路。这次范围大得多，同样的数据量摊到每块区域上就少了。
2. **三个控制器的学习曲线都比预测陡**：数据从 30 % 加到 100 %，误差比是 0.70–0.75，预测是 0.78–0.97。到 3 万次重置还远没有饱和。
3. **姿态误差的改善比预测大**：
   - ScaleBFM 从 43.7° 降到 6.9°（−84 %），HEFT 从 19.9° 降到 5.9°（−71 %），SONIC 从 36.0° 降到 10.8°（−70 %）；
   - 预测是降 30–70 %。

   ScaleBFM 不用模型时的姿态误差最大，模型修正后反而最准。
4. **HEFT 的长伸手并不少**：val 里 1112/1492 段超过 2.5 s，这些段的误差只是总体的 1.10 倍，预测是 1.2–2.5 倍。
   - 跑离的段都截在跑离之前，剩下的长伸手 HEFT 都撑住了。
   - 但 val 里有 837/2539 段因为摔倒或跑离被排除，相当一部分空间没有标签。
5. **SONIC 最低一档（z < 0.3）不比总体难**：倍数 0.94/1.01，预测 1.1–1.8。
6. **最难的一档是 z ≥ 1.2**：倍数 1.22–1.75。HEFT 在这一档 7.0 cm，蹲着时 5.2 cm、站着时 3.0 cm，是所有格里离总体最远的，但都没有超过 2 倍。

## 结论与下一步

- **三个控制器在 LML 宿主里都学出了自身模型。** 同一套采法、同一套模型代码，100 % 数据时：

  | 控制器 | 位置误差（val / test） | 直接执行 | 比值 | 姿态误差降幅 |
  |---|---|---|---|---|
  | ScaleBFM | 3.08 / 3.00 cm | 9.61 / 9.49 cm | 0.32 | 84 % |
  | HEFT | 3.99 / 3.90 cm | 10.67 / 10.52 cm | 0.37 | 71 % |
  | SONIC | 4.25 / 4.15 cm | 14.28 / 14.04 cm | 0.30 | 70 % |

  - 左右手相差最多 14 %。
  - 先走路的误差是原地的 1.05–1.29 倍。
  - 滚转 > 40° 和 |偏转| > 60° 这两块新补的朝向，只比总体差 0–10 %。
  - 没有任何一块超过总体 2 倍。
- **证据强度**：
  - 每个控制器 1 个 seed；
  - 每次评估 1492–3094 段，来自 1206–2256 次重置；
  - 区间按重置重抽样得出；
  - 只在宿主仿真里、只在验证分布上评估，还没有用真实任务局检验。
- **其他可能的解释**：
  - ScaleBFM 不如预测，也可能是这套配方（3 万步、batch 1024）对更大、更杂的输入空间不够，不只是数据少。学习曲线陡说明数据确实是主要因素，但两者没分开。
  - HEFT 的数是在"没摔倒、没跑离"的子集上算的，它的覆盖本来就窄，比值 0.37 不能直接和另外两个控制器比。
- **四类陷阱**：
  - benchmark 选择：评估集是 data.py 按重置划分的 val 和 test_iid，拆分维度登记时就定了，所有格都报了。
  - 数据泄漏：划分和 hostdata 相同，按重置编号分；frac 是按重置嵌套抽的子集，验证集不变。
  - 指标误用：用的是登记时的中位数、比值和区间，val 和 test 都报了。
  - 事后挑选：每个配置只训了一次，checkpoint 由 train.py 按 val 挑。val 参与了挑 checkpoint，以 test_iid 为准引用。
- **对照判据**：
  - "从 30 % 到 100 % 还降 10 % 以上"三个控制器都触发了，所以要加采。data3b 就是加采，合并训练另外登记，加采做到降幅小于 5 % 为止。
  - "先走路 ≤ 1.2 倍原地"ScaleBFM 和 SONIC 在两个划分上都成立，以后可以少采走路；HEFT 的 test 是 1.29，不算。
  - 其余判据都没有触发：比值最大 0.37；单格最大倍数 1.75；左右手最多差 14 %；三个控制器的姿态误差都降了。
- **还缺什么**：
  - 用真实任务局检验预测误差，并检查起始状态在不在训练范围里。按用户的规则当天就要做，另外登记。
  - 合并训练。

> - 总体的 3–4 cm 是这两群平均出来的。HEFT 第二次伸手的比值 0.60–0.63 超过了条目自己定的 0.5 线，只是判据按控制器总体定，字面上没有触发。
> - 和第二次伸手相交的格子会超过 2 倍：第二次 × z ≥ 1.2，ScaleBFM 是总体的 2.20 / 1.83 倍，SONIC 2.26 / 2.26 倍；HEFT 的蹲 × z ≥ 1.2 是 2.37 / 2.46 倍。这些是从 190 个两两组合里挑的，有多重比较的成分，但"第二次 × 高处"在两个集、两个控制器上都重复出现。
> - 学习曲线也分两群：30 % → 100 %，第一次伸手降 29–39 %（比值 0.61–0.71），第二次只降 19–26 %（0.74–0.81）；两群差距随数据增多拉大，ScaleBFM 在 10 %、30 %、100 % 时第二次 / 第一次是 2.0、2.4、3.1 倍。
> - 一部分像是缺输入：同一只手连续伸两次时，第二次的模型误差随上一次落空的距离上升，SONIC 4.9 → 8.4 cm（相关 0.30），HEFT 5.4 → 8.2 cm，ScaleBFM 4.0 → 5.1 cm。上一次落空的距离就是这次发命令时手和参考之间的差，这次训练没开 `REACHWM_X0_REF`，模型看不到。
> - 但主要还是起点姿态更多样：即使上一次几乎没落空，第二次的误差也是第一次的 1.7–2.5 倍。
>
> ### 4. 可能推翻主要结论的实验
> **实验 A（针对第 1、2 条）：把"起点是否接在上一次动作之后"登记成正式拆分，用新数据检验。** 每个控制器新采 2000 次重置（新种子、新重置编号），每次先做一次随机伸手（不进评估，照常停稳），再做一次评估伸手；另采 2000 次和现在一样的"默认站姿第一次伸手"作对照。直接用冻结的 frac 1.0 模型评估，不重训。每个控制器约 4000 个评估段，ScaleBFM 50 进程约半小时，HEFT 跑离多要多采约一半。推翻条件：某个控制器在"接在上一次之后"的起点上比值 > 0.5，第 1 条对它不成立（现有数据里 HEFT 已经是 0.60–0.63）；这一格 > 2 倍总体，或它和高度段相交的格 > 2 倍，第 2 条不成立；如果有真实任务的起点（LocoManiLab 任务局）也照样评估，超过 val 的 2 倍，就说明"没有一格超过 2 倍"不能外推到实际使用。
>
> **实验 B（针对第 3 条）：不加采，先看曲线在 100 % 附近还陡不陡、瓶颈是不是数据。**
> - B1：在现有数据上补训 frac 0.5、0.7（seed 0），再训 frac 1.0 的 seed 1、2，三个控制器共 12 次，每次 15–20 min 一张卡（`train.py` 的 `--frac` 只接受 0.1、0.3、1，要直接调 `train()`）。推翻条件：0.5 → 1.0 的降幅 < 10 %，或 frac 1.0 三个 seed 之间的差达到 30 % → 100 % 降幅的一半以上。
> - B2：frac 1.0 打开 `REACHWM_X0_REF=1`，让模型看到发命令时参考手的位置及它和实测手的差，三个控制器各训一次。推翻条件：第二次伸手误差的降幅不小于 3.3 倍数据带来的降幅（ScaleBFM 6.56 → 5.21，即 ≥ 21 %），那样"先加采"就不是最划算的下一步，应先补输入。
> - B3（贵但最直接）：给 ScaleBFM 再采 3 万次重置（约 3.5 h），用 2 倍数据重训。按现在的曲线（误差约正比于数据量的 −0.26 次方），总体应降到约 2.6 cm、第二次伸手约 4.6 cm。推翻条件：实际降幅 < 5 %。
>
> ### 5. 判定
>
> | 主要结论 | 判定 | 理由 |
> |---|---|---|
> | 1. 三个控制器都学出了模型：比值 0.30–0.37，姿态误差降 70–84 % | **支持，但要加限定** | 数字核对无误（SONIC test 的姿态降幅是 69 %）。换成"命令 + 固定偏移""IK 规划朝向"这些更强的基线，模型仍明显更好。限定：① 只对"从默认站姿或走完停稳后的第一次伸手"很强；从上一次伸手的姿态接着伸，比值 ScaleBFM 0.49、SONIC 0.43、HEFT 0.60–0.63，HEFT 这部分不能说学出来了。② HEFT 的总体数被跑离筛选抬高了，可比口径约 4.5 cm / 0.43。 |
> | 2. 没有哪一格超过总体的 2 倍 | **按字面支持；它背后的推论不支持** | 登记的单维拆分里确实没有一格超过 2 倍，最高 HEFT z ≥ 1.2：val 1.75 倍（区间上沿 2.13），val+test 合并 1.54 倍，算上未停稳 1.80 倍。但条目假设要的是"没有哪一块明显学不好"：按第几次伸手分开就有 2.4–3.3 倍的差，第二次 × 高处超过 2 倍；评估不含 edge（0.05–0.08 m 高度、过中线 0.5 m 以上），那里最高 2.46 倍。 |
> | 3. 学习曲线还很陡，30 % → 100 % 降 25–30 %，所以要加采 | **降幅和"按判据要加采"：支持；"再采同样的数据就能把难的那部分降下来"：证据不足** | 降幅核对无误（val 26–28 %，test 25–30 %），frac 按整次重置嵌套抽，和挑检查点无关。但只有一个 seed；陡的主要是误差已只有 1.6–2.9 cm 的第一次伸手；第二次伸手只降 19–26 %，还有缺输入的迹象。按现在的斜率外推，要把第二次伸手的误差减半，需要 16–57 倍的数据。 |

### 复核后的更正

1. **姿态降幅改为 69–84 %**：SONIC 在 test 上是 69 %，原来写的"70–84 %"不对。
2. **SONIC 的训练卡**：修订 1 的卡表写的是 4090b，实际用的是 4090 的 3 号卡，是在 13:29Z 开训前由采集 agent 改的，修订 1 里并没有附注这一条。另外，冻结清单还应列上 `wm.py` 和 `fk.py`，这两个文件和 9deae006 逐字节相同。
3. **收回"以后可以少采走路"**。只拿第一次伸手比，ScaleBFM 先走路的误差是原地的 1.31 / 1.18 倍，HEFT 是 1.26 / 1.33 倍。原来的 1.14 是两次伸手混在一起算的，把差别冲淡了。只有 SONIC 在只比第一次伸手时也不到 1.2 倍。
4. **结论一要加限定**：
   - 第一次伸手（从默认站姿或走完停稳出发）学得很好，比值 0.18–0.29。
   - 接着上一次姿态的第二次伸手，误差是第一次的 2.4–3.3 倍，比值 ScaleBFM 0.49、SONIC 0.43、HEFT 0.60–0.63。HEFT 的第二次伸手不能算学出来了。
   - 和其他控制器横比时，HEFT 应该用约 4.5 cm / 0.43。
5. **结论二只在登记的单维拆分上成立**：
   - "第二次伸手 × 高处"超过 2 倍。
   - band 和 edge 两组没有评估，其中 edge 里 z < 0.08 m 那部分，ScaleBFM 是 2.46 倍。
6. **结论三**："按判据要加采"成立，但"只靠加采就能把第二次伸手降下来"证据不足：
   - 第二次伸手误差随上一次落空的距离变大，说明可能缺了"手和参考之间的差"这个输入（`REACHWM_X0_REF`）。
   - 这一点和用户关心的"从停稳的抬手出发"正好是同一件事。data3b 有 3/4 的伸手是从抬手出发的。
   - 合并训练加一组 `REACHWM_X0_REF=1`，并按第几次伸手拆开报，写进 train3b 的修订 0。
7. **只报中位数不够**：p90 的比值，ScaleBFM 0.51、HEFT 0.58、SONIC 0.38。伸手 ≤ 2.5 s 的那一格，HEFT 和 SONIC 的比值是 0.45–0.49。以后报告里都要带上 p90。
