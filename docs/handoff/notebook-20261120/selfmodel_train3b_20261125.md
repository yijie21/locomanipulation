## 模型（每个控制器都一样）

| 名字 | 训练数据 | seed | 用来回答什么 |

## 度量

所有误差都是中位数，区间按重置重抽样，取 95 %。val 和 test_iid 都报，以 test_iid 为准。

- **data3 的 val 和 test_iid**：看合并以后，原来那块分布上的误差有没有变差。按 train3 的方式拆开报。
- **data3b 的 val 和 test_iid，按伸手种类拆开**：
  - 进入段；
  - 预抓取段；
  - 相对伸手，分 < 15 cm、15–30 cm、> 30 cm 三档；
  - 进入段里，手离抓取点 8–17 cm、手腕要转 < 20° 的那一格单独报。
- **LocoManiLab 真实局**：用 [selfmodel_lmlreal_20261125](selfmodel_lmlreal_20261125.md) 记下的伸手离线评估，第一下和第二下分开报。
- **比值**：
  - M / T3：data3b 的进入段上、data3 上、真实局第二下上各算一次；
  - D / M：看 3 个 seed 的平均，再看 seed 之间的范围；
  - 学习曲线：frac 1.0 对 0.3 的比值。
- **位置误差和姿态误差都报**，还要报"手停在命令处"时的直接执行误差。

## 假设

1. data3 里几乎没有"停稳的抬手 + 短距离 + 小转腕"这种伸手，所以 T3 在这一下上会明显变差。M 补上了这一块，误差应该回到其他伸手的水平，而且原来那块分布上的误差不会变差。
2. 在已经有真实进入段的情况下，中间点样本的帮助会小很多。relabel 测试里 A/C = 0.56，那是在完全没有进入段的前提下。

## 预测

- **data3b 的进入段**：
  - T3 的误差是它在 data3 val 上的 1.5–3.5 倍；
  - M/T3 在 0.3–0.7 之间；
  - M 在进入段上的误差，是 M 自己在 data3 val 上的 0.8–1.5 倍。
- **data3 的 val 和 test**：M/T3 在 0.85–1.02 之间。
- **真实局第二下**：M/T3 在 0.5–0.85 之间；第一下在 0.85–1.05 之间。
- **D/M**：
  - 进入段上 0.85–1.02，原来那块分布上 0.92–1.02；
  - 3 个 seed 之间的区间会把 1.0 包进去，或者只是勉强不包。
- **合并以后的学习曲线**：frac 1.0 对 0.3 的比值在 0.75–0.90，曲线还在降，但比 train3（0.70–0.75）平一些。
- **三个控制器的方向一致**。HEFT 因为跑离多、数据少，区间会更宽。

## 判据

| 结果 | 结论和下一步 |
|---|---|
| data3b 进入段上 M/T3 ≤ 0.7，且区间上限 < 0.85 | 补采有效，M 作为这个控制器的主模型 |
| data3b 进入段上 M/T3 > 0.85 | 补采没把这一下补准。先查进入段的标签和停稳；再看是不是数据量不够（学习曲线） |
| data3 上 M 比 T3 差 5 % 以上 | 合并伤到了原来的分布。查两份数据的比例，考虑重新加权（另行登记） |
| D/M ≤ 0.95，3 个 seed 都 < 1.0 | 以后的配方加入中间点样本 |
| D/M 在 0.95–1.0 之间，或者各 seed 方向不一致 | 不加中间点样本，配方保持简单 |
| D/M > 1.0 | 不加中间点样本 |
| 合并后 frac 1.0 对 0.3 仍降 10 % 以上 | 下一轮继续加采，重点放在误差最大的几格 |
| 合并后 frac 1.0 对 0.3 降不到 5 % | 这一轮停止加采 |
| 真实局第二下的误差仍 > 2 倍 val | 找出是哪些量落在范围外，针对它们补采 |

### 修订 0：train3 复核以后、合并训练开始以前（2026-11-25）

原有的预测和判据不改，下面只做补充。起因是 train3 的独立复核发现：第二次伸手，也就是从上一次伸手留下的姿态出发的那一下，误差是第一次伸手的 2.4–3.3 倍。四个比值：

第二次伸手的误差还会随上一次落空的距离变大，相关系数最高 0.30。这说明模型可能缺一个输入：发命令时，手和控制器参考之间差多少。data.py 里已经有 `REACHWM_X0_REF` 这个开关，打开后会把发命令时的参考手点，以及它和实测手点的差，一起放进 x0。"从停稳的抬手出发"正是第二次伸手这种情况；data3b 里有 3/4 的伸手属于这一类。

**补充 1：所有评估都按"第几次伸手"拆开**

- 先走路和原地的比较，只在第一次伸手上做。train3 里把两次伸手混在一起算，差别被冲淡了。

### 修订 2：开训前的第二次修订，MX 的输入改成"这一下计划的参考起点"（2026-11-25）

预测和判据都不改。

**发现的问题**

C 行记的参考手点，要换回实测的世界坐标才能用。`d3_collect` 换算时，在 k0 那一行减的是上一个计划的 xy 平移（d_prev），从 k0+1 起才改用这一下计划自己的平移（d_this）。

data.py 的 X0_REF 读的正是 k0 那一行。所以它读到的"参考 − 实测"里混进了根节点的漂移：
- 先走路的第一次伸手，混进的是整段走路的漂移：HEFT 32 cm，SONIC 34 cm，ScaleBFM 10 cm。
- 接着上一次的伸手，混进的是上一条命令之后根节点的漂移，中位数约 5 cm。

如果改用这一下的平移，"参考 − 实测"的中位数变成：
- 先走路：HEFT 4.0、SONIC 2.3、ScaleBFM 2.2 cm；
- 接着上一次：HEFT 3.6、ScaleBFM 4.1、SONIC 5.5 cm。

停稳那一行用的本来就是这一下的平移，所以修订 1 的核对结果（差 0.000 cm）不受影响。

**决定**

1. **MX（主臂，判据只按它算）**：data.py 不改，只给 MX 单独准备一份输入数据，把每一段的 C[k0,:3] 换掉。新的值取这一下计划的第一帧参考手点，也就是 k0+1 那一行用 d_this 换算到世界坐标的结果，再换回 k0 时刻的骨盆坐标系。
   - 这个量的含义是：这一下计划从哪里出发，和手实际在哪里，差多少。部署时也能同样算出来。
   - 误差只来自 k0 到 k0+1 这 0.1 s 里骨盆的移动。开训前先把它量出来：停稳的起点应在 0.2 cm 以内，超过 0.5 cm 就先停下报告。
   - seed 0、1、2，判据和修订 0 相同。
2. **MXa（副臂，只描述，不参与判据）**：按原样读存下的 C[k0]，只训 seed 0。
   - 对接着上一次的伸手，这个量大体等于上一下落空了多少。train3 的复核看到误差和上一下的落空相关，用的就是这个量。
   - 训它是为了看，"上一下落空了多少"这个信息本身有没有用。

### 修订 3：MX 改用精确算法算参考起点（2026-11-25，MX 和 MXa 还没开训）

预测和判据都不改。

**修订 2 的理解错在哪**：新计划的第一帧不是 k0+1，而是 k0 时刻参考正好停着的位姿（代码里 `shifted = [ref_pose] + 计划位姿[1:]`），只是要用这一下的平移 d_this 来换算。k0+1 那一行的参考已经沿第一段走了约一半（min-jerk 跑了 0.1 s，进度约 0.52）。所以修订 2 的简单做法误差有 2.8–3.5 cm（中位数），超过了它自己定的 0.5 cm 停止线，MX 已经按规则停下。

**精确算法**：记 X 为这一下计划的参考起点（世界系），Cw 为存下的 C[k0] 换回世界系的值，W 为 k0 时刻的实测根节点，分三种情况：

| 情况 | 参考停在哪 | 怎么算 X | 核对 |
|---|---|---|---|
| 第一次伸手、原地 | 起始站姿，d_prev = 0 | X = Cw + W_xy | 所有重置的 Cw 每只手都是同一个点，标准差 0.02 cm |
| 第一次伸手、先走路 | 走路终点的站姿 | X = Cw − (walk_cmd_xy − Rz(起步朝向)·walk_real_xy) | 和"目标站姿的手点放到实测根节点上"这个独立预测相比，差的中位数 0.001–0.004 cm，最大约 0.6 cm；存下的 Cw 和这个预测差 10–32 cm |
| 接着上一次 | 上一下计划的末位姿 | X = Cw − (上一段 ref_pel_xy − W_xy) | 上一段在 data/、data_both/ 或 data_detour/ 里都能找到。没有独立预测可以对，依据是代码，以及 k0 那一行和上一段结束行逐字节相同 |

最后一步换到 k0 的骨盆系：C'[k0,:3] = R_k0ᵀ (X − p_k0)。

data.py 不改，只给 MX 单独准备一份输入数据，每段只改 C[k0,:3] 这一行，其余数组逐字节相同。生成脚本在正式数据上再把上面的核对跑一遍，任何一项不过就不训 MX。

| 控制器 | 第一次·原地 | 第一次·先走路 | 接着上一次 |
|---|---|---|---|
| HEFT | 4.1 / 4.2 cm | 5.8 / 8.2 cm | 6.4 / 16.5 cm |
| ScaleBFM | 1.8 / 2.0 cm | 2.1 / 4.0 cm | 7.2 / 15.7 cm |
| SONIC | 2.2 / 2.5 cm | 2.4 / 3.5 cm | 10.0 / 27.9 cm |

**其他安排**：
- MXa 照修订 2，读存下的 C[k0]，只训 seed 0，只作描述。
- 流水线里 M、D 照常训。MX 用 3 个 seed，和 MXa 一起另外启动，代码另外冻结。全部训完后，T3、M、D、MX、MXa 放进同一张表评估一次。
