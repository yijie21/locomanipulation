## 1. ASPIRE 是什么

| 部分 | 做什么 | 位置 |
|---|---|---|
| 执行引擎 `cap_harness` | LLM 写的 Python 程序在受限沙盒里跑：只许 `import math`，AST 校验拒绝类、`with`、下划线属性；只能调公开 API（感知 SAM3、抓取 Contact-GraspNet、IK PyRoki、规划 cuRobo、`move_to_pose` 等）。每次调用记一个带父子关系的 span（输入输出摘要、耗时、错误码和数值细节），运动前后各存关键帧，每拍写 `steps.jsonl`。 | `src/cap_harness/runtime.py`、`api.py`、`artifacts.py`、`contracts.py` |
| 迭代调试 | **每个任务一个程序**。子代理在开发种子上按失败模式（不按种子）改版本：每版跑全部开发种子，每个模式最多 3 版、总共 8 版；选通过最多的那版，在“未见检查”种子上只测一次。协调者再跑留出种子（LIBERO 1–50、Robosuite 1–100）。 | `iterative-debugging/main-agent-prompt.md`、`subagent-prompt.md` |
| 技能库 | 按主题分的 markdown（定位、抓取、搬运、操作）。每条写触发条件、5–20 行代码、为什么有效加证据、局限；子代理逐条打分（有用、误导、错误、不适用）；提议的新条目先由**验证者**只凭文字在 5 个种子、2 版之内重做出来（≥ 4/5）才能收进库。 | `skills/README.md`、`verifier-prompt.md`、`scripts/lint_skills.py` |
| 进化搜索 | 难任务每轮写 K=8 个各验一个假设的候选，在 15 个开发种子上评，从前三名继续；≥ 80% 或 5 轮或连续两轮提升不到 5 个点就停。 | `evosearch/` |
| BEHAVIOR 协议 | R1 Pro 移动底盘（全向，cuRobo 底盘规划，失败时沿可通行图每次跳 1 m），长程任务一个代码块一个代码块地长；第二阶段库冻结，每个评测种子派新代理、最多 12 次尝试。 | `iterative-debugging/behavior/` |
| 真机 System 2 | YAM 双臂经 MCP 工具操作（魔方、拧瓶盖等），提示词式的执行守则。 | `AGENTS.md`、`docs/system2.md` |

报告的成绩：v1.0 README 说 80 个 LIBERO-Pro 任务 99%；论文 v1（Opus 4.6）LIBERO-Pro 总体 72%，Robosuite 81%，BEHAVIOR 两个任务 88%。成绩随模型变化很大：10 个 LIBERO-Pro 任务从 15%（GPT-6 Luna）到 99%（Opus 5.5）。

## 2. 用 RSI 专家的眼光看

专家先问五件事：改进的是什么，测的是什么，测法靠不靠得住，功劳记在谁身上，经验会不会累积。

### 2.1 做得好的：把“认识上的纪律”写进了流程

这些都是从真实事故里倒推出来的规则，`lint_skills.py` 自己说“每条检查都是追溯的，没有一条凭空发明”。

- **知识要过三道关才算数**：
  - 提议只是说法，验证者只凭文字（看不到提议者的程序、笔记、运行记录）能重做出来才收进库；
  - 收进去之后，每个用到它的任务都给它打分；
  - 打成“错误”的先修，修好之前不派新任务（`main-agent-prompt.md:320-328`）。
- **证据规则**：
  - 提议者在自己程序上做的消融只算来历，不算证据（6f）：同一处改动，提议者测 0/15，验证者在自己程序上测 5/5；
  - 只有附和、没有经受过反驳的结论不收（6e）；
  - 每条结论要先问清哪个测量能推翻它。
- **错配分响和闷两种**：响的（IK 拒解、爪子空合）保留宽触发，加一条“可运行的前置检查”；闷的（抓错了物体却报成功）把触发条件收窄。“前置条件要么是代码，要么不算”。
- **库的写法**：
  - 条目只写现在为真的东西，历史挪到 changelog；
  - 纠正要写进代码片段的注释里。他们的 `transport.md` 曾涨到 2.8 万词、六成是评论，结果有个任务照着纠正前的片段做，0/5。
- **工程上**：
  - 程序沙盒（AST 校验，禁用下划线属性、禁止导入）；
  - 产物清单带 sha256；
  - 封存的校验要求干净的 git 树，程序、依赖锁、环境都要哈希一致；
  - BEHAVIOR 冻结的库有 sha256 清单，每次派活前都核对；
  - 有看门狗：代理卡在审批提示上不会报错，只会一直等，曾因此白等 14 h 18 min。

### 2.2 站不住或要打折扣的

1. **没有统计**：全仓库没有置信区间、显著性检验或 Wilson（已 grep 核实）。
   - 门槛是整数计数：验证者要 ≥ 4/5；`robosuite-bimanual.yaml` 的接力只要 1/3。
   - 进化搜索在同一批 15 个开发种子上取 8 个候选里最好的，有“赢家诅咒”，唯一的防线是 15 个未见检查种子。
2. **99% 主要是“每个任务各写一个程序”**：留出种子是同一任务换了起始摆放。能跨任务累积的只有文字库，那部分的证据是：
   - 零样本的库规模曲线：LIBERO-Pro Long 从 4.7% 到 30.5%（N = 0 → 90 个源任务）；
   - 真机 token 用量：举汽水罐总 token 从 61.9M 降到 6.6M，开抽屉从 335M 降到 82M。
3. **BEHAVIOR 的分数是“最多 12 次尝试里成功一次”**：
   - `score_campaign.py` 记的是：最终策略的任何一局成功就算这个种子成功；
   - 他们**故意不报可靠性**；
   - 第二阶段在评测种子上让新代理试错 12 次，每次都由仿真器复位。这是在评测实例上的测试期搜索，不能和一次跑定的策略成功率比。
4. **隔离靠自觉**：
   - 种子划分只查不重叠；
   - 子代理提示词只禁止写、没禁止读自己任务目录里的 `validation/`（留出结果就在那里）；
   - 验证者“看不到答案”只是提示词规定，提示词自己也承认这一点（`verifier-prompt.md:55-58`）；
   - `dispatch.py:148-156` 主动把提议者的留出分数写进验证者可读的文件，还写死成“/50”（Robosuite 是 100）。
5. **我核实过的代码缺陷**：
   - `audit_seeding.py:67-68,103`：签名是字符串，打印的是 Python 的 `hash()`。字符串哈希每个进程加盐，“在新进程再跑一次、比对哈希”这项检查永远过不了。
   - `check_batch_equivalence.py:278`：判定条件是“A/B 不同的种子数 ≤ A/A 不同的种子数”，比的是个数，不是逐种子；而且批跑会重设 `random` 和 `np.random`（`batch.py:192-195`），单跑不会，A/B 的差别和种子方式混在一起。
   - `score_campaign.py:96-99`：没有可评局的种子直接从分母里去掉。
   - `run_validation.py` 只看 `task_success`，程序报错但任务完成也算通过（他们写明了这个规则）。
6. **成本不进账**：引擎里没有 token、费用或轮数统计，也没有上限，只能事后从 Claude Code 转录里加总（`trace_stats.py`）。
7. **模型依赖**：同一框架 15% 到 99%，框架和模型各贡献多少分不开。
8. **库的维护**没有解决：论文局限里承认条目会过时、冗余、误导，零样本曲线不单调可能与此有关。

一句话：**流程纪律和产物工程很好，测量很弱**。最值得借的是“知识怎么进库、怎么被打分、怎么被反驳”这一层；它的统计、隔离和评分方式不能照搬。

### 3.2 我们比它强、不该换的

- 验收：配对 McNemar 门、Wilson 区间、隐藏的封存池、转录泄漏检查（`loop.transcript_leaks`）、写回后所有族加所有标定样本的配对回归（`regress.py`）。ASPIRE 没有统计，也没有跨版本的回归登记。
- 可做性预测：检查器、分桶和三批标定。ASPIRE 没有对应物，排序靠协调者在 `curriculum.md` 里写判断。
- 预算：每个内环有费用、时间、门数上限，ledger 按角色记账。ASPIRE 的引擎不记成本。
- “物理上做不到”要用户确认才能搁置。ASPIRE 的 blocked 是代理自己写一页说明。
- 确定性：我们验过 2 个进程和 12 个进程逐局相同。它的等价检查只比个数，还和种子方式混在一起。

### 3.3 和我们无关的

- **搬运掉落、滑移、手掌蠕滑**：本 session 剩下的检查器误判主要是这一类。ASPIRE 的 API 里没有滑移或掉落检测，BEHAVIOR 只在终局检查“握着并高出 5 mm”。它没有人形、没有全身控制，底盘是全向的，不涉及走路时手里拿着东西的问题。
- **非特权感知**：它禁止程序读仿真器状态，一律走 SAM3 加点云。我们的专家按设计用特权状态（用来给 VLA 生成数据，见记忆“privileged teacher”）。这不是缺口，但写论文时不能拿我们的数和它的比，前提不同。
- **执行引擎代码**：和 LIBERO、Robosuite、OmniGibson 以及它的感知服务绑定，程序是“只能 `import math` 的脚本”。我们的技能是被所有任务共用、要做回归的 Python 模块，跑在 MuJoCo 加 ScaleBFM 上。不能直接用。

## 4. 怎么判断它是否有利于我们

1. **只引进针对已量到的问题的东西**：先在 ledger、回放或标定里找到问题，再看它有没有对应做法；不因为它是新的最好结果就引进。
2. **分层判断**：
   - 能借的是协议层（知识怎么进库、打分、反驳）和少量工程层（错误码、span 树、冻结清单）；
   - 执行引擎和适配器层不搬；
   - 测量层用我们自己的。
3. **每项引进都用我们现有的量具，事先定好指标，配同条件对照**：
   - Reviewer 层面用 `review_replay.py`：费用、分钟、轮数、最好的探针、有没有找到已知的好线索。§12.2 量过重跑方差大，每臂至少 2 次。
   - 技能层面用门和封存池。
   - 检查器层面用标定。
4. **代价**：许可是 Apache 2.0，拷代码或提示词要保留 NOTICE；它执行模型生成的代码不设防，它的 README 也这么警告，我们只读不跑。

## 5. 建议（按收益排序；第 1、2 条花模型费，待用户定）

1. **试一个“经验库”，用回放来量**（约 50 USD 模型费，主要是 Reviewer 回放）：
   - 把技能 docstring 和方案里反复出现的跨族事实，整理成按触发条件写的条目：触发条件、代码或数、证据、局限，只写现在为真的。例子：滑移 0.062 cm/s 和指垫余量、`into.release_fit` 的 1 cm、低处夹的条件、大白花瓶挡夹爪。
   - 用 `review_replay.py` 在 r2_in、r2_on 第 0 轮比较“摘要加经验库”和“只有摘要”，每臂 2 次。
   - 指标：费用、轮数、最好的探针、有没有找到已知的好线索。
   - 过了再接进内环：Reviewer 给读过的条目打分，提议的新条目要经过验证才进库。
2. **在第 1 条之后，给技能 docstring 定规矩**：只写现在为真的，历史挪到 changelog（照它的 6d）；量 Reviewer 实际读了多少字。
3. **步骤失败加错误码**：在保留自由文本 why 的同时加 `code` 字段，让摘要、标定、检查器对照按码归类。不花模型费，属于基础设施改动。
4. **不借**：它的成功率记法、无统计的门槛、BEHAVIOR 的计分。往后在论文或对外材料里引用它的数时，要注明它是每任务各写一个程序，BEHAVIOR 是测试期多次尝试。
