**冻结规则**：§2、§3 的门槛和致命条件，§4 的判据和格子，在引入本文的那次提交里冻结（`git log --follow` 本文的第一条）。之后只许加测，不许改门槛；要改，先在 DECISIONS 单记一条并写明原因，再改本文。

## 1. 范围与对象

- **替换范围**：仿真专家采集、仿真 VLA 闭环评测、真机部署三处都换。VLA 学得好不好**不进判据**。
- **机器人**：bottle 的 L1 / L2 用 stock G1（场景 `bottle` = `outputs/scene/sim_lowcom`，生产配置 `configs/experiments/bottle_simple_200.yaml`）；warehouse 的 L1 / L2、复杂动作 C1–C7 和 S1 用 mars（场景 `warehouse_box_*_mars`，生产配置 `configs/experiments/warehouse_mars_200.yaml`，只走 ym 边）。ScaleBFM 是在 stock 上训的，所以 W0 是准入关。
- **ScaleBFM**：checkpoint M 22200（`configs/backend/scalebfm.yaml`），能力全开：每个动作用实测最好的 mode（§5），不锁在 mode 2。XL 不测。
- **SONIC**：v1.1（`policy/sonic_v1_1`，真机部署用的同一个）。每个动作用它最好的接口：planner 指令、VR_3PT、streamed 29 关节参考三选一；哪个都表达不了就记"不能表达"，这本身是结果。
- **定位**：L1 / L2 两边都用仿真真值。另设一臂"估计位姿"（§4.5）。

## 2. 最终判据（冻结）

**主判据**：L2 任务成功率，每个场景至少 40 局，同种子配对，两边交替先后。ScaleBFM 在两个场景的点估计都 ≥ SONIC，且至少一个场景 exact McNemar p < 0.05。

**护栏**（每个场景、每 40 局）：摔倒次数 ≤ SONIC + 1；掉物次数 ≤ SONIC + 1；ego 相机角速度 p95 ≤ SONIC × 1.2。

**否决**（任一条成立就判"不能替换"）：

1. **a 否决**（10-13 开跑前用户改：力矩按 50 N·m 测，摔倒不太高就不否决）：力矩就是 mars 标称——腰 roll / pitch 50 N·m（`make_dex1_model.MARS_EFFORT_OVERRIDES`）、踝 35 N·m（真机固件值，mars 场景本来就是）。ScaleBFM 在 W0 或 a 套用的项（W2、W4、C1、C5、C6）里，任一项 10 次中摔倒 ≥ 3 次才否决。
2. **h 否决**：ScaleBFM 一步推理（含目标关键点的 FK 和观测拼装）p99 > 20 ms。机载电脑型号未知：先在本机用同一 TensorRT 版本测下限，本机就超 20 ms 立即否决；本机不超的，到真机阶段在机载电脑上复测。
3. **真机组合档否决**：L2 真机组合档（§6）任一场景 ScaleBFM 成功率点估计比 SONIC 低 10 个百分点以上。

**结论不一致时**：两个场景结论不同就分开报告；目标是一个控制器统管两个场景，"按场景各用各的"只作退路，由用户定。

**否决关失败时**：整个计划停下，先查原因（例如 W0 摔倒是 mars 的惯量还是腰的力矩）再汇报，由用户决定修了再跑还是放弃替换。

## 3. L1 致命短板（冻结；任一条成立就不移植专家、不进 L2）

1. W0 不过：mars 标称参数下站 30 s、走 1.5 m、弯腰到两种箱高（0.18 / 0.33 m），任一项 10 次中摔倒 ≥ 3 次（同 §2 a 否决）。
2. a 或 h 否决（§2）。
3. 生产档任一 L1 项的摔倒率高于 SONIC（W0 和 a 套用的项按第 1 条的绝对阈值，不和 SONIC 比）。
4. 现有专家必须用到的动作，ScaleBFM 用任何 mode 都交付不了。例：bottle 专家实际走进去后的站位上，抓取姿态大部分落在 ScaleBFM 交付不了的虎口朝右区域（24.6 的包络：31/156，全在虎口朝左）。

其余"比 SONIC 差但不致命"的项只记录，不挡移植。

## 4. L1 原语层

每格 10 次，报 mean ± sd 和最差一次。ScaleBFM 仿真确定性，重复局抖初始条件（起点 ±10 cm、yaw ±3°，和 24.7 的抖线同理）；SONIC 靠出生和步态自带散布。

**格子分两档**，报告里分开列：

- **生产档**：各场景采集配置的随机化范围，抽 10 个种子。用来判替换。
- **外推档**：每项往现有范围外扩一圈，用来看上限、不进判据。例：B1 速度到 0.7 m/s、起始 yaw ±40°；B3 / W3 目标超出现有专家的距离和高度；W4 负载 2.4 kg；W1 停位距离扫 0.20–0.35 m（跨过 SONIC 的 0.265 / 0.28 m 成败边界），另外三条边 xm / xp / yp。

### 4.1 bottle（stock，单臂）

| 项 | 测什么 | 主要读数 |
|---|---|---|
| B1 走到桌边停位 | 0.25 / 0.35 / 0.55 m/s 走到专家的站位目标 | 距离误差、站位 yaw 误差（14° 是 SONIC 线的成败分界）、横向误差 |
| B2 停稳用时 | 专家要求腿和底盘静止 0.5 s 才接管手臂 | 停到静止的时间 |

| B4 手腕动态跟踪 | 沿 simple 专家的真实路径：抬手 → 滑到预抓 → 8 cm/s 进入 | 跟踪误差、滞后（SONIC 0.2 s 的滞后会碰倒瓶子） |
| B5 伸手时身体副作用 | 同 B4 | 骨盆漂移、脚滑、腰扭转角、躯干前倾 |
| B6 合爪和提起 | 合爪、提起、保持 2 s | 合爪时手抖 RMS、提起后掌系滑移 |
| B7 拿着瓶子走路 | 直走 1 / 2 m、转 90° / 180° | 掌系漂移（SONIC 原地转 180° 会滑 3 cm） |
| B8 头部相机稳定性 | 走路、伸手、刹车三段 | ego 相机角速度、目标在画面里的位移 |

### 4.3 复杂动作 C1–C7（mars）

C1 地面拾取（z ≈ 0–0.1 m），C2 高处够取（1.3–1.5 m），C3 边走边伸手、走动中合爪，C4 侧移 / 后退 / 原地转身（空手和带载），C5 深弯腰越过桌面（躯干前倾 60–80°），C6 双臂从地面搬箱，C7 右手递左手。C8 地形、C9 外力交互不测。

- **参考片段**：通用身体动作用公开的 G1 重定向 LAFAN1（Unitree 在 HF 上那份），标"分布内"（两个控制器很可能都训过）；任务化动作（C3、C5、C6、C7）用 IK 关键帧合成，标"分布外"。本机目前没有任何 G1 重定向片段，要先下载。Pico 真机录制推到真机阶段。
- **两边怎么吃同一个片段**：SONIC 走 streamed 29 关节；ScaleBFM 用片段 FK 出的关键点，按 §5 选 mode。
- **读数**：摔倒率、G-MPKPE、局部 MPKPE（和 ScaleBFM 论文同口径，可以对照论文的 0.09 m）。任务化片段另加关键帧判据：手离目标 ≤ 5 cm、姿态偏差 ≤ 15°，持续 0.5 s。
- **成功** = 不摔，并且关键帧判据通过；通用片段没有关键帧，用 G-MPKPE ≤ 0.1 m。

### 4.4 S1 mode 切换瞬态

L2 里实际用到的每一种切换（例如走路 0 → 伸手 2 → 抱起 7），测切换前后 0.5 s 的骨盆跳变、脚滑、手腕跳变和摔倒率。新加入的关键点在切换那一拍用实测姿态的 FK 初始化。SONIC 的接口切换（planner ↔ streamed）同样测。

### 4.5 估计位姿臂

在仿真里写一个真实的估计器：关节编码器做腿运动学，加支撑脚判定和 IMU 姿态，积分出骨盆位姿；输入只用仿真传感器读数，并加 c 项噪声。用它代替真值重跑：刹车（24.7 协议）、B1、W1，以及 VLA 执行器每拍的重锚定。这个估计器也直接搬进真机部署程序。若估计位姿下 ScaleBFM 的刹车和停位优势掉到 SONIC 的水平，真机上的停位优势就不成立。

### 4.6 真机扰动 a–h

| 扰动 | 套用的项 |
|---|---|
| a 力矩 = mars 标称（腰 50、踝 35 N·m），即 mars 场景本身，不另设档 | W0、W2、W4、C1、C5、C6 |
| b 动作延迟 +20 / +40 ms | B1、B4、W1、W3、刹车 |
| c 观测噪声（IMU 角速度、关节速度） | B1、B4、W1、B7、W6 |
| d 地面摩擦 0.4–1.0 | B1、W1、C4、刹车 |
| e 负载 ±50% | B6、B7、W4、W5、W6 |
| f PD 增益 ±20% | B4、W3、C2 |
| g 骨盆推扰 50–100 N × 0.2 s | 站立、B7、W6（带载） |
| h 机载算力 | 单独测，不用仿真 |

## 5. mode 选择

mode 表（`assets/scalebfm/mode_table.pt`）：0 骨盆；1 双腕；2 骨盆 + 双腕（现用）；3 双腕 + 双踝；4 骨盆 + 双腕 + 双踝；5 上身 6 点（双肩、双肘、双腕）；6 骨盆 + 上身 6 点；7 全身 14 点。只有 mode 7 能给躯干和膝盖下目标。

每个动作把能表达它的 mode 全扫一遍，各 10 次，按成功率、再按误差挑最好的，固定下来给 L2 用。报告"最好的 mode 比 mode 2 好多少"。mode 3–7 要的脚、肘、膝参考：能力测试用 §4.3 的片段；任务程序要不要写全身参考生成器（IK + 落脚点），等 L1 证明 mode 3–7 确实有用再定。

## 6. L2 任务层（L1 过关后才做）

- **bottle**：主臂把 SONIC simple 专家的程序移植到 ScaleBFM（只换控制器，同 24.3 `bfm_grasp.py` 的做法）。参考臂是 ScaleBFM 已有的视觉专家（`tasks/bottle_visual`，信息边界不同），有余力再跑。
- **warehouse**：移植现行四边专家（`warehouse_mars_200.yaml`），各段换成 §5 选出的 mode。
- **两档**：标称档；真机组合档 = b（20 ms）+ c + f 同时加，力矩按场景标称（a 已并入标称）。
- **SONIC 公平性**：每局记 RTF，RTF < 0.9 的局作废重跑；跑 SONIC 时机器上不跑 ScaleBFM；两边都用当次全新跑的结果，不复用 TODO 24 以前的数字。

## 7. 真机阶段

- **部署程序**：先写 Python + TensorRT 版，对外接口和 SONIC deploy 一致（读 5557 的 `g1_debug` 状态、收 5556 的指令），推理做成可替换的一层；确认机载电脑后再决定要不要改 C++。先用仿真桥跑 sim2sim。
- **冒烟顺序**（每步过了才往下）：吊架上站 30 s（看关节力矩和抖动）→ 吊架下松绳踏步 → 落地站立 → 走 1 m → 刹车到标线 → 单臂伸手到格点。急停用 SONIC 现有的键盘 / 手柄链路。SONIC 同一天、同一块场地逐步做对照。由用户团队操作；脚本、判据和记录表由这条线准备。
- **未知**：机载电脑型号、实验室有没有外部定位。默认按没有：停位和手位用卷尺加地面标线量，ScaleBFM 的世界锚定只靠 §4.5 的里程计。
