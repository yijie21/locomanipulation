# 检查采集视频：固定10集随机化覆盖检查

以后对助手说 **“检查采集视频”**，即可调用本流程；若刚修改过场景或随机化，使用修改后的当前代码。
该请求只授权运行这项有界检查，不表示恢复已取消的Goal或启动训练。

在仓库根目录执行：

```bash
bash scripts/scalebfm_video_check.sh
```

## 固定要求

1. 使用当前采集专家、当前场景资产和当前随机化分布，真实执行10集完整动作。
2. 先用采样器生成候选重置，不调用物理或策略；按瓶子沿边位置、向内深度、机器人起步距离、横移、朝向偏差挑选差异较大的组合。
3. 当前三个场景分配高近4集、低近3集、低深3集。每类先取接近中间值的代表，再补充其它参数区间与组合。计划在运行前保存，不根据抓取成功挑选、补抽或隐去失败。
4. 全部导出第三视角MP4：800×696（含96像素信息栏），25fps，原速，包含启动、走近、伸手、抓取及结束状态。
5. 镜头从机器人右侧略偏前方观察，随骨盆位置及朝向平滑跟随；始终在其前半空间，避免背面视角。自动拉远以容纳头、四肢、手掌、脚部及瓶子。
6. 每帧检查投影边界与相机是否落到背后；每条视频做ffprobe帧数、分辨率、帧率检查。保留代表帧供人工确认遮挡；投影入镜不等于无遮挡。
7. 视频标注场景、seed、瓶子位置、起步参数、时间、阶段、结果；同时导出网页播放目录、总览图、参数计划、逐集审计及10条视频打包下载。
8. 成功与失败均保留。它是覆盖式行为检查，不是随机抽样成功率评估，也不是VLA训练/闭环测试；不写入正式训练集。

## 资源、复用与恢复

默认只使用CPU单线程和OSMesa，隐藏CUDA，不启动录制stack、不占其它会话端口。原Goal保持停止。
仍先读 `docs/STATE.md`，不得使用 `stop_stack.sh` 或终止其它任务。

输出默认在 `outputs/videos/scalebfm_check10_<场景分布>_<配置哈希>/`。
配置哈希包括采集源码、专家参数、模型和场景资产；修改后自动进入新目录。
相同配置重复调用会复用已完成轨迹和完整视频；不会因为某集失败而重新抽取。
同目录有文件锁，拒绝重复启动。中断后如果物理已经完整保存则可补元数据；若只有部分轨迹则明确报错，不自动重跑掩盖中断。

只查看候选计划，不运行机器人：

```bash
bash scripts/scalebfm_video_check.sh --plan-only
```

当前默认 `--scene-profile yplus_center_v1`。若明确检查历史三侧规则，可传 `--scene-profile legacy_edges_v1`。
可用 `--out <目录>` 指定位置，但已有目录的源码/配置不匹配时会拒绝覆盖。
自定义场景目录通过现有 `SCENE_DIR` 环境变量指定。

如果以后增减场景层或新增随机化维度，要同步扩展 `STRATUM_ORDER` 和检查器的覆盖参数；五个连续维度的分箱覆盖不代表全部联合组合均被测试。
当前不是恢复扰动专项检查，10集均为普通初始化；停早/遮挡/物体移动等恢复扰动需要另行指定。
