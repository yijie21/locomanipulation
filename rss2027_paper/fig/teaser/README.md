## 选局规则（事先定好，没有挑）

1. **配对**：ScaleBFM 判定集是 6 个任务（蜡烛、苹果、盐瓶、雕像柜、哑铃、浇水壶，去掉碗），局号 30–119，共 540 对。其中"A 失败、R 成功"的有 **138 对**，和 lmlroute 的 eval.txt 一致（R vs A：R-only 138）。138 对都有合手距离。
2. **合手距离**：局记录里的 `close_dist_cm`，即合手那一步手点到抓取点 `plan.goal` 的距离。lrt_eval 的 "close-time hand to the grasp point" 用的也是这个量。
3. **中位数**（138 对）：A 6.444 cm，R 1.134 cm。没有并列值。
4. **百分位**：每局在本臂 138 个值里的百分位，p = 100 ×（比它小的个数 + 0.5 × 和它相等的个数）/ 138，也就是 scipy `percentileofscore` 的 `kind='mean'`。这样中位数正好落在 50。
5. **排序**：分数 = max(|pA − 50|, |pR − 50|)，从小到大；同分时局号小的在前。
6. **换一种百分位定义**（`kind='rank'`）：前 8 名的顺序不变，第一名还是蜡烛 117。

## 复现核对

**怎么重放的**：
- lmlroute 冻结代码的私有副本：vePFS `loco_outputs/fig1_teaser_20261126/code/`，1120 个文件的 md5 和 `asrun/CODE_MD5` 相同；输入、那一眼的 md5 也和 asrun 相同。
- 在 H20b 上用冻结的 `lrt_run.run` 重跑这一局，A、R 在同一个进程里先后跑。环境和正式运行的 worker 相同：只用 CPU、单线程、nice 19。正式运行时这一局在 H20 上跑。
- 代码自检通过：所有模块都来自私有副本，副本以外的模块 0 个。
- lmlroute 没有存每一步的完整状态，所以是重跑出来的。合手那一步用一个只读钩子保存了完整的 MuJoCo 状态和模型。

- **局记录里没有合手时手和物体的位置向量**，只有上面两个 float64 距离，和每 0.1 s 一行的手点。两个距离都逐位相同，整局记录也逐位相同。
- **合手帧不在 0.1 s 的网格上**：最近一行，A 早 2 帧（手又动了 0.005 cm），R 早 10 帧（0.039 cm），只作参考。
- **渲染用的状态就是记录量出这些距离时的状态**：
  - 仿真 `mj_step` 之后，MjData 的位姿属于这一步开始时；
  - 渲染时用存下来的 body / geom 位姿；
  - 从渲染状态算出的手点、物体位置，和合手时的采样差 0 m，算出的合手距离也逐位相同；
  - 如果改用 qpos 重新 `mj_forward`，会差一个物理步，最多 5e-5 m。
- **A、R 是同一个场景**：两个模型的 MJB 文件 md5 相同（b45f5c47）。

## 渲染设置

- **渲染器**：MuJoCo 3.3.1 自带的 `mujoco.Renderer`，离屏 EGL（`MUJOCO_GL=egl`，`CUDA_VISIBLE_DEVICES=2`，`MUJOCO_EGL_DEVICE_ID=2`），H20b 的 2 号卡。H20b 上本来就有 libEGL，没有装任何东西。
- **几何**：只显示 geom 组 1、2（场景的视觉网格）。组 0 是碰撞体，按 robosuite 的惯例隐藏；不隐藏的话，机器人是绿色的碰撞外形。
- **画质**：
  - 抗锯齿 `vis.quality.offsamples = 16`；
  - 阴影 `shadowsize = 4096`。
- **灯光**：
  - 模型原有的 5 盏灯都保留；
  - 另加一盏柔和的主光：平行光，diffuse 0.35，specular 0.05，投阴影；从上方来，向相机一侧偏 25°。偏得太多的话，墙会在地板上投下大片阴影。
- **背景**：相机在浴室里面，画面里没有一个像素看到空处（0 像素）。所以浅灰底色（236, 236, 236）的合成没有起作用，背景就是浴室的墙。
- **尺寸**：3600 × 2400（3:2），按 1200–1800 px 的成图宽度算，是 2–3 倍。
- **叠加**：直接在 MuJoCo 里叠。
  - 先渲 A 的状态，再用 `mjv_addGeoms` 把 R 的机器人作为一个副本加进同一个场景（只加机器人的 geom）；
  - 统一着色 RGB (0, 114, 178)、alpha 0.40、emission 0.25；
  - 受光照和多层半透明叠加影响，看上去比 (0, 114, 178) 亮一些；
  - 两个机器人重合的地方（腿、躯干）有少量 A 的灰色透出来，这是两个副本几乎重合造成的。

## 相机（两个臂完全相同）

**选法**：
1. **筛选**：在合手时刻周围搜了 720 个自由相机。方位是相对机器人朝向 0–345°（每 15°），俯角 15–45°，距离 1.6–3.2 m。
2. **有效视角的条件**，两个臂都要满足（`render/.../search.json`）：
   - 相机到物体、到手的连线上没有家具；
   - 物体至少 50 % 可见，被家具挡住 ≤ 5 %，被手以外的机器人部件挡住 ≤ 5 %；
   - 手至少 40 % 可见，被家具挡住 ≤ 10 %；
   - 整个机器人都在画面里。

   结果 100 个有效。
3. **挑选**：在"稍高、偏侧面"的范围里按眼挑的。没有事先写打分规则。

**选中的主相机**：
- 方位是机器人朝向 + 150°，相机在机器人正前方偏右 30°；俯角 30°，距离 2.0 m。
- **物体**：A 可见 97 %；R 可见 61 %，其余 39 % 是 R 自己正在合拢的手挡住的。被手臂挡住 0 %，被家具挡住 0 %。
- **手**：可见 100 % / 99 %。

**特写**：
- 方位、俯角和主相机相同，距离 0.6 m；
- 注视点是两个臂的手点和物体的平均位置；
- 尺寸也是 3600 × 2400。

- **坐标约定**：
  - X_cam = R · X_world + t，相机系 x 向右、y 向下、z 向前（OpenCV 约定）；

- **核对过**：
  - MuJoCo 单目渲染用的是左右两眼相机的平均（`mjv_averageCamera`），外参取的就是这个平均；
